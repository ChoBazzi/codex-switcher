# 0005. 사용량 조회, 사전 전환 임계값 및 무재시도 오류 처리

- 상태: accepted (ADR 0009에 따라 복구 정책 갱신)
- 날짜: 2026-09-05

## 결정 배경

두 계정의 사용량을 관측하고 다음 세션용 계정을 준비한다. 실패 요청은 같은 계정이나 다른 계정에 자동 재전송하지 않으며 사용자 입력을 기다린다.

## 검토한 선택지

1. 안전한 요청에 한해 자동 재시도: 초기 결정이었으나 중복 실행 및 CLI 재시도 충돌을 줄이기 위해 폐기.
2. 모든 실패 요청 자동 재시도 금지 (선택): 실패를 명확히 표시하고 다음 세션은 사용자 입력으로 시작.

## 최종 결정

- 사용량은 기본 60초 정기 조회와 사용자 수동 새로고침으로 수집한다. 실패 후 즉시·백오프 재시도는 추가하지 않는다. 기존 정기 일정은 유지한다.
- 429만으로 exhausted를 설정하지 않는다. 명확한 한도 소진은 exhausted, 일시 제한은 cooldown으로 구분한다.
- 신규 세션 사전 전환 임계값은 기본 90% 소진이며 80~95%로 조절한다. Wiki 작성 임계값 50%·10%와는 별도 정책이다.
- 기존 세션의 계정·continuation 소유권은 유지한다. 한도 소진 또는 수동 전환은 다음 세션용 계정을 준비하며 실패한 요청을 옮기지 않는다.
- 추론·인증·로그인·Wiki 작성·사용량 조회 실패를 자동 재시도하지 않는다. 정기 토큰 유지보수와 정기 사용량 조회는 실패 요청의 재생과 구분한다.
- 응답 시작 전에는 원인에 맞는 HTTP 상태와 호환 JSON 오류를 반환한다. 인증·형식·서버 오류를 일괄 429로 바꾸지 않는다.
- HTTP 헤더나 SSE를 전달한 뒤에는 상태 코드를 변경하지 않는다. 검증된 스트림 오류 또는 연결 종료로 실패를 전달한다.
- CLI 자체 재시도 및 HTTP 클라이언트의 숨은 재전송을 비활성화하고 검증한다. 사용자 입력 여부를 판별할 수 없다면 실패 세션 차단과 명시적인 새 세션 식별로 재전송을 막는다.

## 예상되는 결과와 단점

- 자동 복구를 줄여 중복 실행과 처리 여부 불명확성을 관리한다.
- 일시적 장애도 사용자 개입이 필요할 수 있다.
- 다음 계정 준비는 모델 호출을 발생시키지 않으며 사용자 입력 이전 자동 작업 재개는 없다.

## 검증

- 합성 401, 429, 5xx, timeout, 스트림 중단에서 실패한 요청의 upstream 재전송이 없는지 확인한다.
- 응답 시작 후 HTTP 429 JSON을 새로 쓰지 않는지 확인한다.
- 계정 준비 후 사용자 입력이 없으면 대상 계정 모델 호출이 0회인지 확인한다.
