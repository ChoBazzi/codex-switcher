# ADR 0047: 최대 5개 계정과 빈자리 추가

- 상태: accepted
- 날짜: 2026-09-10
- 관련: ADR 0035, 0042, 0046, 0004

## 결정

후속 [ADR 0050](0050-account-grid-and-cache-refresh-feedback.md)에서 아래 스크롤 목록을 창 너비 620pt의 2열 × 최대 3행 그리드로 대체하고 로그아웃 확인을 공통 인라인 영역으로 이동했다.

사용자 요청으로 기존 2개 제한을 최대 5개로 변경한다. 내부 슬롯은 A~E로 고정하고 계정 추가는 확인된 첫 빈자리를 사용한다. 카드 목록에는 등록 계정과 인증 오류/작업 상태를 표시한다. 여러 카드와 인라인 로그아웃 확인은 스크롤 영역에 배치한다. 기존 A/B 인증·슬롯 순서는 보존하며 재번호를 부여하지 않는다.

5개가 등록되면 추가는 비활성화한다. 인증 만료/사용량 소진도 등록 수에 포함한다. 미확인/저장 오류를 빈자리로 간주하지 않는다. 앱은 계정 작업을 직렬화하고 백엔드의 프로세스 잠금·occupied 검사·계정/사용자 복합 ID 중복 검사를 유지한다. 취소/실패로 등록되지 않은 슬롯은 다시 사용할 수 있다.

로그인/로그아웃 완료 후 프록시는 해당 슬롯의 로컬 인증을 확인하여 등록 상태를 바로 표시한다. 이 확인은 모델/사용량 API를 호출하지 않는다. 변경 시작 시 사용량 무효화 및 in-flight 조회 세대 검사는 유지한다. 사용량은 다음 60초 주기에서만 갱신하며 새 계정의 이전 사용량은 복원하지 않는다. 로그아웃 성공으로 미등록이 확인된 현재 슬롯은 다음 새 요청에서 다른 사용 가능 계정을 선택할 수 있다. 실제 실패 요청 재전송은 하지 않는다.

초기/자동 전환 후보는 A~E 전체다. 최신 잔여량 5% 초과 중 가장 큰 계정을 선택하고 동률은 슬롯 순서, 사용 가능한 현재 계정은 유지한다. 기존 수동 A/B 실험 시작 조건은 보존하되 C~E도 명시적으로 선택할 수 있다. 미등록 슬롯은 로컬 확인만 하고 외부 사용량 조회를 보내지 않는다.

Keychain 서비스 키와 registry version 1을 유지하며 레코드 상한만 5로 확장한다. 제한된 토큰 필드 5개 레코드를 수용하도록 전체 보관 바이트 상한은 128 KiB에서 512 KiB로 늘린다. 이전 바이너리는 3개 이상 저장된 registry를 읽지 못하므로 새 앱/helper를 함께 사용한다.

영속 affinity DB는 schema version 3으로 기존 sessions/handoffs의 슬롯 CHECK를 확장한다. 단일 트랜잭션에서 복사·교체하고 외래 키 검사를 수행한다. 기존 response 소유권·인계 예약은 보존하며 실패 시 롤백한다. 이전 바이너리는 v3 DB 사용을 거절한다. 사용자 저장소 초기화 및 실제 계정 변경을 개발 검사에서 수행하지 않는다.

## 검증

### 네이티브 Keychain 크기 경계 보완

Go의 512 KiB 저장 상한과 달리 네이티브 읽기에 128 KiB 상수가 남아 있던 불일치를 수정했다. 읽기 함수에 Go `MaxBytes`를 전달해 복사/할당 전 같은 상한을 검사한다. 기존 저장 데이터나 서비스 키를 변경하지 않는다.

`TestNativeKeychain`은 별도의 무작위 합성 항목으로 128 KiB + 1, 256 KiB, 정확히 `MaxBytes`를 저장·새 인스턴스로 재조회하고 작은 값으로 갱신한다. 빈 값 및 상한 초과 저장 거절 후 기존 값 보존도 확인한다. `SWITCHER_KEYCHAIN_INTEGRATION=1`인 경우에만 실행하며 macOS Keychain 접근 권한이 필요하다. 일반 테스트의 `TestKeychainWriteSizeGuard`는 실제 Keychain 호출 없이 잘못된 크기를 검사한다.

### 계정 목록 및 로그인 중단 보완

사용량 미표시 보고에서 helper의 조회 정상 응답을 확인했다. 메뉴바의 content-fitting 과정에서 목록이 접히지 않도록 ScrollView의 최대 높이만 지정하던 코드를 명시적 viewport 높이로 수정한다. 실제 사용자 화면 재현은 별도 검증하며, 합성 파이프 검사에 빈 슬롯 4개와 정상 사용량 계정 1개 조합을 추가한다.

기존 Codex 브라우저 OAuth는 탭 종료 이벤트를 앱에 전달하지 않는다. 창 종료를 인증 실패로 추정하거나 임의로 busy를 해제하지 않는다. 로그인 취소를 계정 목록/스크롤과 무관한 상단에 표시하며, 취소 시 helper 종료·저장 상태 재확인 이후 추가를 허용한다. 최대 305초 자동 취소는 유지한다. 합성 대기 helper로 시간 초과·단일 완료 콜백·재로그인 가능 여부를 검사한다.

합성 검사: 5개 등록/6번째 거절/중복/로그아웃 후 재사용/다른 계정 보존, C~E quota 및 제어, 빈자리 UI 상태·로그아웃 확인, A/B DB migration과 소유권 보존. 전체 `sh macos/Checks/verify.sh`로 빌드와 회귀 검사를 수행한다. 실제 브라우저 OAuth 5회와 메뉴바 클릭/스크롤은 사용자 수동 검증 대상이다.
