# 0006. Codex Wiki 작성과 다음 세션 인계

- 상태: accepted (ADR 0009에 따라 작성 주체·격리·재개 정책 갱신)
- 날짜: 2026-09-05

## 결정 배경

현재 작업 중인 Codex가 작업 맥락을 Wiki로 남기고 다음 세션의 Codex가 참조한다. 이전 요청이나 서버 대화 상태를 다른 계정에서 자동 재생하지 않는다.

## 검토한 선택지

1. 전역 저장만 사용: 프로젝트에서 확인하기 어렵다.
2. 프로젝트 최신본만 사용: 프로젝트 삭제 시 백업이 없다.
3. 세션별 프로젝트 최신본과 전역 최근 3개 백업 (선택): 작업별 격리와 가시성을 함께 확보한다.
4. 별도 요약 모델: 추가 호출과 맥락 수집 비용이 있어 선택하지 않는다. 현재 Codex가 작성한다.

## 최종 결정

### 저장과 격리

- 로컬: `<repo>/.codex-switcher/<worktree-hash>/<branch-hash>/<session-id>/checkpoint.md`.
- 전역: `~/.codex/switcher/projects/<project-hash>/<worktree-hash>/<branch-hash>/<session-id>/`에 최근 3개 스냅샷.
- 정규화된 프로젝트·worktree 경로와 브랜치 식별자의 해시, 검증된 내부 session ID로 경로를 구성한다. detached HEAD와 Git이 없는 프로젝트도 별도 식별한다.
- 동일 프로젝트의 여러 세션이 덮어쓰지 않게 한다. 경로 해시만으로 접근 격리를 보장한다고 가정하지 않고 인계 원본 세션을 검증한다.
- 임시 파일 작성 후 원자적 교체하며 실패 시 이전 유효본을 보존한다.
- 저장 완료는 ADR 0010에 따라 Go helper가 checkpoint_id·원본·지정 경로·필수 항목을 모델 호출 없이 확인한다. 검증한 바이트를 인계 스냅샷으로 고정하며 저장 성공과 안전한 작업 경계 확인을 구분한다.
- 새 세션은 인계에 지정된 원본 세션의 Wiki를 참조하고 이후에는 자신의 별도 경로에 기록한다.

### 작성 주체와 시점

- 현재 Codex가 Wiki를 작성한다. 프록시는 임계값과 요청 전달·인계 준비를 담당한다.
- 잔여량 50%·10%에서 각각 한 번 자동 작성을 예약한다. 잔여량 기준은 단기·장기 한도 중 작은 값이며 필요한 데이터가 unknown이면 추정하지 않는다.
- 도구 실행 결과가 확정된 안전한 작업 경계에서 작성한다. 매 턴이나 매 polling마다 작성하지 않는다.
- 세션·계정·한도 윈도우별 처리 여부를 영속화하여 재시작·수치 변동으로 재작성하지 않는다. 실제 해당 윈도우 갱신 때만 기록을 재설정한다.
- 이미 임계값 아래에서 시작하거나 두 임계값을 한 번에 통과하면 한 번만 작성하고 해당 임계값들을 처리한 것으로 기록한다.
- 수동 전환은 현재 Codex의 최신 Wiki 저장을 확인한 후 다음 세션을 준비한다. 예약된 자동 작성과 중복되면 한 번으로 합친다.
- 작성 실패는 재시도하지 않는다. 기존 Wiki를 보존하고 전환을 중단하며 사용자 조치를 기다린다.
- 계정 소진 후 긴급 요약은 요청하지 않는다. 자동 전환 준비에는 마지막 Wiki를 사용하되 정보 부족·결과 불명확성을 표시한다. 수동 전환의 작성 실패를 오래된 Wiki로 묵시적으로 대체하지 않는다.

### 인계와 재개

- 목표, 변경 파일·브랜치와 변경 요약, 결정 사항, 다음 TODO를 기록한다. 저장 시각과 완료 여부가 불명확한 작업을 구분한다.
- 불필요한 전체 재탐색은 줄이되 오래된 정보와 실행 결과는 필요한 범위에서 확인한다. 토큰 절감률은 측정 전 보장하지 않는다.
- 인증 정보와 서버 continuation ID는 Wiki에 포함하지 않는다.
- 준비 후 사용자 입력을 기다린다. 사용자 입력 이후 다음 세션의 Codex가 Wiki를 참조하며 이전 대화 전체를 자동 재생하지 않는다.
- Wiki 읽기·요약·개발 재개를 위해 사용자 입력 전에 B를 호출하지 않는다.
- 원본 세션은 A에 유지하고 새 세션만 B에 바인딩한다. 인계 실패는 자동 재시도하지 않는다.

## 검증이 필요한 연동

CLI 연결은 프록시 방식으로 유지한다. 프록시 경유 작성 지시 전달, Codex 저장 완료 확인, 다음 세션 생성·식별 및 Wiki 참조 연결을 검증해야 한다. 프록시가 CLI 수명주기 제어 기능을 자동으로 갖는 것은 아니다. 미지원 시 사용자에게 Wiki 작성과 다음 세션 시작을 안내하고 기다린다.

## 예상되는 결과와 단점

- 요약 시점을 제한하고 다음 세션은 사용자 의도로 시작한다.
- 마지막 체크포인트 이후의 작업이 누락될 수 있으며 잔여량 10%에서도 작성 완료는 보장되지 않는다.
- 프로젝트별 여러 CLI 세션과 worktree의 상태가 섞이지 않도록 저장 및 인계 식별이 필요하다.

## 수용 기준

- 51% → 49% → 48%에서 한 번, 이후 11% → 9%에서 추가 한 번 작성한다.
- 60% → 8%에서는 한 번만 작성하고 재시작 후 중복 생성하지 않는다.
- 수동 전환은 저장 성공 전 준비 완료로 표시하지 않는다. 실패 후 반복 호출은 없다.
- 사용자 입력 이전 B의 모델 요청은 0회이고 이후 명시된 원본 Wiki를 참조한다.
- 동시 세션·worktree·브랜치 간 덮어쓰기와 잘못된 원본 선택이 없고 저장 실패 시 이전 유효본이 보존된다.
