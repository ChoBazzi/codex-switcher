# ADR 0050: 두 열 계정 목록과 캐시 새로고침 피드백

- 상태: accepted
- 관련: ADR 0046, 0047

후속 [ADR 0051](0051-explicit-usage-refresh.md)에서 캐시 읽기를 실제 사용량 조회로 변경했다. 아래 3초 응답 대기·캐시 완료 안내는 이전 동작이며, UI 배치 결정은 유지한다.

## 결정

사용자가 창 너비 확대와 2열 × 최대 3행 배치를 승인했다. 메뉴 너비는 620pt, 계정 카드는 287pt 두 열로 표시한다. 고정 높이 ScrollView를 제거하고 eager Grid의 실제 콘텐츠 크기를 사용한다. 최대 다섯 계정을 슬롯 순서로 표시하며 마지막 빈 칸은 계정/등록 자리로 오인하지 않도록 비워 둔다. 계정 추가는 기존 상단 버튼을 유지한다.

현재 선택된 계정은 배경색·테두리·문구로 함께 구별한다. 선택 표시가 요청 진행을 뜻하지는 않으며, 프록시 연결을 확인할 수 없으면 계정 카드의 선택 강조를 해제한다. 로그아웃은 모달을 재도입하지 않고 그리드 아래 공통 인라인 확인 영역을 사용한다. 취소 및 정확한 대상 슬롯 확인 정책은 유지한다.

사용량 새로고침처럼 보이던 버튼은 기존 설계상 외부 조회가 아닌 캐시 읽기였다. `캐시 새로고침`이라는 이름과 도움말로 범위를 표시하고, 읽기 중/완료/실패를 알린다. 완료 시각은 앱이 캐시 응답을 받은 시각이며 카드의 `마지막 확인`은 원본 조회 성공 시각으로 그대로 둔다. 값이 같아도 캐시 확인 완료를 표시한다. 개별 계정 조회 실패는 카드 상태로 유지하며 캐시 수신 성공을 외부 조회 성공으로 취급하지 않는다.

프록시 제어 연결이 확인된 경우에만 클릭할 수 있다. 응답 대기 중 중복 클릭을 차단하고 3초 시간 초과, 잘못된 데이터, 연결 종료 시 대기 상태를 해제한다. 자동 재요청은 없으며 사용자가 재확인할 수 있다. 같은 프로세스에서 수신한 정상 usage snapshot은 정기 발행 여부와 무관하게 최신 캐시로 반영한다. 세대와 요청 식별자로 이전 타이머가 다음 작업을 종료하지 않도록 한다. 프록시의 60초 외부 조회·단일 데이터 원천·오래된 정보 판정은 변경하지 않는다.

## 검증

- DirectProxyCheck: 실제 합성 자식 파이프로 캐시 수신, 연타 억제, 응답 누락 시간 초과, 잘못된 응답, 수동 복구, 종료 후 비활성화 확인.
- TestProbeUsageSingleSource: 반복 캐시 읽기가 외부 조회를 추가하지 않음.
- MenuLayoutCheck: 실계정/네트워크 없는 데모로 0/1/2/3/5개 계정을 light/dark SwiftUI ImageRenderer로 렌더링하고 620pt 너비 및 높이 상한 확인. ImageRenderer에서 네이티브 Picker는 대체 표시되므로 실제 메뉴바 컨트롤 동작 검증을 대신하지 않는다.
- verify.sh: Go 회귀·설치 CLI 합성 검사·Swift 빌드·기존 로그인/로그아웃 검사와 위 검사 실행.
- 수동 확인: 실제 메뉴바에서 다섯 계정과 하단 버튼이 보이는지, 긴 오류 문구/로그인 취소/로그아웃 확인 상태에서 잘림이 없는지 확인한다. 합성 렌더는 실제 디스플레이의 메뉴바 배치 및 모든 접근성 글꼴 크기를 보증하지 않는다.

Lazyweb 도구가 세션에 없어 디자인 리포트는 생성하지 않았다. 사용자 지정 배치를 구현했으며 외부 디자인 근거가 확보되었다고 주장하지 않는다. 새 의존성은 없다.
