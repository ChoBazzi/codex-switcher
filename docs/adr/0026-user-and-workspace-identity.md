# ADR 0026: 사용자와 워크스페이스의 복합 계정 식별

- 상태: accepted
- 날짜: 2026-09-06
- 관련: ADR 0013

## 배경

Business의 서로 다른 사용자 등록 시 `account_already_registered`가 보고됐다. 기존 코드는 `tokens.account_id` 하나만 사용자 고유 ID처럼 취급했다. 실제 실패 원본은 보존하지 않으므로 두 사용자의 원본 claim 차이는 아직 실증하지 않았다. 대화방/프로젝트 세션은 로그인 중복 검사에 관여하지 않는다.

## 결정

- 동일 계정은 `(AccountID, UserID)` 두 값이 모두 같을 때로 정의한다. 같은 워크스페이스의 다른 사용자, 같은 사용자의 다른 워크스페이스는 서로 다른 조합이다. 새 슬롯 등록, 재인증, 저장된 registry 중복 검증에 같은 기준을 쓴다.
- AccountID는 기존 `tokens.account_id`를 유지한다. UserID는 access token의 `https://api.openai.com/auth.chatgpt_user_id`에서 파생한다. UserID를 독립 JSON 필드로 입력받거나 저장하지 않으며 토큰에서 매번 복원한다. 이메일, 토큰 문자열, 프로젝트 ID 및 의미가 다른 `sub`를 추정 대체값으로 쓰지 않는다.
- 새 로그인에서 사용자 claim이 없거나 유효하지 않으면 `account_user_identity_unavailable`로 거절한다. 토큰 형식·만료·account claim 일치 검사는 유지한다. claim 디코딩은 서명 검증이나 서버 인증 성공을 의미하지 않는다.
- 기존 v1 Keychain 자료와 슬롯/세션 매핑을 유지한다. 읽기만으로 vault를 쓰지 않는다. 기존 토큰에 사용자 claim이 있으면 즉시 복합 비교에 활용한다. 기존 claim이 없는 단일 계정의 상태/사용량 조회는 유지하되, 같은 AccountID 추가나 재인증 시 신원을 추정하지 않고 거절한다. 이 경우 원본 삭제나 임의 마이그레이션은 하지 않는다.
- 같은 워크스페이스의 다른 사용자가 재인증으로 기존 슬롯을 덮어쓰는 것도 거절한다. 기존 서버 헤더 `ChatGPT-Account-ID`는 변경하지 않고 사용자 ID를 헤더/로그/제어 응답에 추가하지 않는다. quota가 두 사용자 사이에 독립이라는 보장은 이 식별 변경만으로 제공하지 않는다.
- 저장된 두 조합이 완전히 같거나, 같은 AccountID인데 사용자 구분이 불가능하면 손상/모호한 registry로 거절한다. 초기화하거나 덮어쓰지 않는다.

## 검증 및 호환성

합성 토큰으로 같은 워크스페이스의 다른 사용자 등록·재시작, 동일 조합 거절, 재인증 시 사용자 또는 워크스페이스 변경 거절, 기존 자료 읽기 무변경, 사용자 claim 누락/잘못된 값 거절과 상태 출력 비노출을 검사한다.

[공식 인증 문서](https://learn.chatgpt.com/docs/auth)는 사용자 로그인과 워크스페이스 선택을 구분한다. 다만 위 JWT claim 이름/의미의 안정적인 공개 계약은 확인되지 않았으므로 제한된 호환 adapter로 취급한다. 실제 Business B 로그인에서 claim 제공 여부와 조합 구분을 사용자 환경에서 추가 검증한다. API 키·OAuth 토큰 재발급을 자동 실행하지 않는다. 외부 의존성 및 Keychain 스키마 추가 없음.
