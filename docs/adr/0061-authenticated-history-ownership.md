# ADR 0061: 인증 신원과 로그인 등록 세대에 따른 내부 이력 격리

- 상태: accepted
- 날짜: 2026-09-21
- 관련: ADR 0043, 0049, 0053, 0055, 0058

## 배경

루트 대화의 현재 턴 reasoning과 도구 이력은 직전 슬롯 이름으로 소유권을 확인했다. 슬롯을 로그아웃하고 다른 계정을 등록해도 이름은 같으므로 이 조건만으로 인증 신원 일치를 보장할 수 없다. 기존 native 압축과 보조 대화는 토큰 해시도 확인하지만, 대상 계정 헤더와 로그인 등록 세대까지 함께 확인하지 않았다.

## 결정

- 계정 관리자가 신뢰하는 인증 자료에서 계정 ID와 토큰의 사용자 ID를 가져온다. 슬롯, 클라이언트 헤더 또는 사용자 제공 JSON 필드를 신원의 근거로 사용하지 않는다.
- 로그인과 명시적 재인증 성공 때마다 새 무작위 등록 세대를 Keychain 계정 레코드에 저장한다. 로그아웃은 해당 레코드를 제거한다. 같은 토큰·계정으로 같은 슬롯에 재등록해도 이전 등록 세대는 재사용하지 않는다. 정상 토큰 갱신은 등록 세대를 유지한다.
- 이력 소유권은 버전 구분값·계정 ID·사용자 ID·등록 세대·실제 사용한 access token을 모호하지 않게 인코딩한 SHA-256 해시로 확인한다. 원문 신원·등록 세대·토큰을 로그, 상태 API 또는 checkpoint에 추가하지 않는다. 신원이 없으면 소유권을 추정하지 않는다.
- 루트 현재 턴 이력에는 직전 성공 응답의 슬롯과 인증 해시가 모두 필요하다. 본문 검사 후 `RequestAccess`가 토큰을 갱신할 수 있으므로 실제 dispatch resolver에서도 소유권을 다시 검사한다. 보호된 이력이 없는 새 텍스트 요청은 갱신된 인증으로 진행할 수 있다.
- 현재 턴 reasoning은 같은 대화의 성공한 upstream 응답에서 실제 관측한 항목만 허용한다. 암호화 내용과 서버 item ID의 해시를 인증 해시에 귀속시켜 메모리에 보관한다. 새 계정의 첫 요청이 성공했다는 이유로 이전 계정의 임의 암호화 항목을 다시 주입할 수 없다. 응답 실패 시 등록하지 않으며 사용자 턴·인증 경계마다 교체하고 최대 1,024개로 제한한다. 루트와 각 보조 대화의 레지스트리는 별개다.
- 지난 사용자 턴의 reasoning은 기존처럼 제거하고 완료된 텍스트·도구 쌍은 보존한다. 루트의 과거 도구 call ID 치환에는 인증 해시도 포함해 같은 슬롯 재사용 시에도 분리한다.
- native 압축과 보조 대화에도 같은 인증 해시를 사용한다. 인증이 달라진 보조 대화는 실패 상태로 고정하며, 새로운 명시적 작업만 시작할 수 있다. 실패 요청 자동 재전송은 추가하지 않는다.
- checkpoint에는 직전 루트 인증 해시와 기존 압축 소유권 해시만 저장한다. 일반 reasoning 해시는 복원하지 않으므로 재시작 후 확인할 수 없는 현재 턴 reasoning은 거절하고 새 사용자 입력을 기다린다.

## 호환성과 한계

기존 Keychain 레코드는 수정 없이 읽는다. 등록 세대가 없는 레코드도 계정·사용자·토큰으로 구분하지만 다음 로그인부터 새 세대를 받는다. 사용자 신원이 없는 구형 인증으로 암호화 이력을 이어가지는 않는다.

과거 토큰 전용 해시로 저장된 압축 소유권을 새 형식으로 추정 변환하지 않는다. 구형 압축 항목은 거절되며 새 텍스트 문맥 또는 새 대화가 필요할 수 있다. 기존 CLI 기록은 삭제하지 않는다. 새 checkpoint 필드를 모르는 구형 helper로의 다운그레이드는 새 연결이 필요하다.

토큰 갱신 후 암호화 이력을 계속 사용할 수 있다고 가정하지 않는다. 같은 계정이어도 토큰 변경 시 현재 턴·압축 이력 또는 장기 보조 작업이 차단될 수 있다는 기존 정책을 유지한다. 계정 작업 알림이 누락돼도 매 요청의 실제 인증 해시로 판별하며, 알림만으로 이력 소유권을 승인하지 않는다. 추가 의존성 없음.

## 검증

- `TestHistoryCredential*`: 신원 구성 요소별 분리, 사용자 신원 누락 거절, 동일 토큰 재등록·재인증 후 새 소유권, 계정 관리자 재시작 시 세대 유지.
- `TestProbeHistoryIdentityIsolation`: 루트 reasoning과 native 압축에서 슬롯을 유지한 채 토큰·계정·사용자·등록 세대를 바꾸거나 신원을 누락시키면 추가 upstream 호출 없이 거절. 본문 검사 후 dispatch 시 변경도 검사한다.
- `TestProbeOldReasoningCannotBeRelabeled`: 새 인증으로 텍스트 요청을 완료해도 과거 암호화 항목의 소유권이 바뀌지 않는지 검사한다.
- `TestAuxiliaryHistoryIdentityIsolation`: 보조 대화의 같은 신원 후속 성공, 바뀐 신원으로의 전송 차단과 실패 고정.
- `TestProbeHistoryCheckpointIdentity`: 동일 인증의 압축 이력 복원, 변경 인증·구형 토큰 전용 소유권 거절, reasoning 소유권 추정 복원 금지, checkpoint의 비밀값·원문 부재.

모두 합성 인증과 로컬 upstream을 사용한다. 실제 계정·사용자 daemon을 교체하거나 모델 요청을 생성하지 않는다.

`sh macos/Checks/verify.sh`의 전체 Go race/vet, 합성 CLI 검사, helper·Swift 빌드와 UI 검사를 통과했다. 마지막 검사 조건 보완 후 계정 관리·helper 전체 race 테스트와 관련 설치 CLI 통합 검사, vet 및 helper 빌드를 다시 통과했다.
