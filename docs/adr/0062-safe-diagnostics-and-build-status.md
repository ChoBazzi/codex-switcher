# ADR 0062: 앱의 안전한 요청 진단과 프록시 빌드 비교

- 상태: accepted
- 날짜: 2026-09-21
- 관련: ADR 0054, 0058, 0059, 0060, 0061

2026-09-21: [ADR 0065](0065-proxy-responsiveness-and-verification.md)는 본문 timeout·크기·수신 실패, Keychain 접근 실패, 보조 작업 한도 진단과 개수 표시를 추가한다. 토큰·식별자·원문 비보관 원칙은 유지한다.

## 배경과 결정

2026-09-21: [ADR 0069](0069-authentication-progress-display.md)는 기존 상태 조회에 인증 대기·갱신·취소 후 마무리 상태를 추가한다. 마지막 오류와 별도로 표시하며 인증 진행 상태는 영속 저장하거나 relay 재연결 캐시에 보관하지 않는다.

기존 daemon은 요청 오류 진단을 앱에 전달하거나 재연결 캐시에 보관하지 않았다. 이력 신원 불일치 등 resolver 오류도 `session_unavailable`로 합쳐져 사용자가 원인을 구분하기 어려웠다. 새 helper를 빌드해도 실행 중인 daemon은 이전 바이너리일 수 있으므로 연결된 프로세스의 빌드 확인도 필요하다.

1. 신뢰하는 resolver가 반환하는 소유권 불일치·보조 인증 변경·인증 만료·계정 미등록 오류를 고정 sentinel로 분류한다. 알려진 신원 불일치는 HTTP 409, 인증 문제는 401로 반환한다. 임의 오류 문자열을 응답에 내보내지 않고 기존 `session_unavailable`로 처리한다. 전송 허용 조건과 요청 재시도 정책은 바꾸지 않는다.
2. 루트 요청 및 보조 작업의 실패를 daemon에서 명시적 허용 목록으로 요약해 `probe_diagnostic` 이벤트로 전달한다. 항목은 메인/보조 구분, 고정 원인 코드, 로컬 발생 시각뿐이다. 헤더, 실제 계정/대화 식별자, 토큰, 이력·요청·응답 본문, 원문 오류와 로컬 경로를 포함하지 않는다. Swift에서도 코드와 시각을 다시 검증한다.
3. 메인 대화와 보조 작업별 마지막 오류 한 건씩 메모리에 보관해 relay 재연결 시 재전달한다. 후속 `previous_request_failed` 및 `new_input_required`는 기존 최초 오류를 덮어쓰지 않는다. 성공 요청으로 기록을 지우지 않으며 화면에 현재 작업 상태와 별개인 마지막 오류임을 명시한다. daemon 재시작 후 복원할 영속 로그는 만들지 않는다.
4. Go helper는 프로세스 시작 시 자기 실행 파일의 SHA-256을 계산해 메모리에 고정한다. 이후 파일을 재빌드해 교체해도 실행 중인 daemon의 값은 변하지 않는다. Git commit만 비교하는 방식은 같은 commit의 서로 다른 미커밋 빌드를 구별하지 못하므로 채택하지 않는다.
5. `proxy-connect` relay는 자기 빌드를 `helper_build`로 먼저 내보내고, daemon은 `probe_ready`에 자기 빌드와 제어 프로토콜 버전을 넣는다. 앱은 두 값을 비교한다. 구버전 daemon이 필드를 보내지 않으면 추정하지 않고 미확인으로 표시한다. 앱 버전은 번들 버전이 있을 때 표시하며 소스 실행은 개발 빌드로 표시한다. 앱과 Go 바이너리의 해시를 서로 비교하지 않는다.
6. 앱의 상태·진단 화면은 기존 메뉴바 창 내부에서 전환한다. 오류 설명·사용자 후속 조치, 연결 시 helper와 실행 프록시 빌드, 복사 버튼을 제공한다. 연결 중 재빌드한 파일을 실시간 감시하지 않으며 재연결 시 확인한다. 복사 내용도 허용된 코드·빌드·상태·시각만 포함한다.
7. 빌드가 다르거나 구버전이면 작업 종료 후 앱·프록시를 함께 종료하고 다시 실행하도록 안내한다. 자동 프로세스 종료·재시작·모델 호출·실패 요청 재전송은 하지 않는다. relay 단절 후 보존한 앱 내 마지막 오류는 이전 연결 기록으로 표시하며, 새 연결 시작 시 비우고 daemon의 현재 캐시를 받는다.

추가 의존성 없음. ADR 0054의 원문 진단 비보관 정책은 유지하며, 고정 코드 두 건의 메모리 캐시만 추가한다. 모든 CLI 이력 형식의 지원을 확대하거나 과거 오류의 원인을 소급 판정하는 변경이 아니다.

## 검증

- `TestResolverDiagnosticAllowlist`: 알려진 오류는 정확한 코드로 전달하고 미지 오류/같은 문자열의 임의 오류는 일반 코드로 처리하며 upstream 시도 0회.
- `TestProbeDiagnosticRedaction`: 원문 비밀값·경로·식별자 제거, 고정 형식 분류, 성공 이벤트 제외.
- `TestServiceDiagnosticReconnectAndOriginalCause`: 메인/보조 분리, 최초 원인 유지, 메모리 두 건 제한, relay 재연결 전달.
- `TestAuxiliaryDiagnosticFromParser`: 보조 이력 파서 실패의 구체적 분류 전달과 원문 제외.
- `TestProcessBuildIdentity`, `TestRelayBuildPrecedesLegacyReady`: 실행 빌드 지문, relay 이벤트 순서, 구버전 daemon의 미확인 값 보존.
- `DirectProxyCheck`: 동일/다른/미확인 빌드, 다른 제어 버전, 오류 분리·복사값 정제, 연결 단절 기록 표시.
- `MenuLayoutCheck`: 오류 두 건과 빌드 경고를 표시하는 밝은/어두운 진단 화면의 렌더링과 크기 확인.

실제 계정·사용자 daemon·모델을 호출하지 않는 합성 검증을 사용한다. 실제 메뉴바에서 상태·진단 열기 → 진단 복사 → 계정 목록 복귀를 수동으로 확인할 수 있다.

`sh macos/Checks/verify.sh`의 전체 Go race/vet, 설치 CLI 합성 통합 검사, helper·Swift 빌드와 UI 검사를 통과했다. 빌드 불일치와 오류 두 건을 넣은 진단 화면은 밝은/어두운 모드 모두 620×416으로 렌더링됐으며, 생성된 화면도 확인했다. 실제 사용자 연결의 오류 해결 여부는 새 앱·프록시 적용 후 별도 확인 대상이다.
