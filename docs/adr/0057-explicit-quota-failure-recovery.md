# ADR 0057: 한도 경계 실패 후 명시적 복구와 제어 재연결

- 상태: accepted
- 날짜: 2026-09-12
- 관련: ADR 0042, 0045, 0054, 0055

5% 이하 자동 선택은 정상 요청 경계에서만 실행된다. 도구 턴 중에는 계정이 고정되므로 그 사이 upstream이 실패하면 다음 요청은 선택 전에 `probe_previous_request_failed`로 차단된다. 이 코드는 최초 실패 원인이 아니다. 앱 재실행/relay 재연결은 daemon의 실패 상태를 보존하므로 이를 초기화하는 방법이 아니다.

연결된 실패 상태의 기존 재연결 버튼을 `사용 가능한 계정으로 복구 준비`로 연결한다. 새 `recover` 제어 명령은 revision·실패 상태·HTTP/도구/대기 요청 부재를 검사하고 최신 사용량이 5% 초과인 후보를 선택한다. 암호화 이력이 있으면 기존 소유 계정 조건을 유지한다. 대상이 없거나 조회가 오래됐으면 거절하고 실패 상태를 유지한다. 수동 슬롯 선택도 그대로 가능하다.

복구 준비는 메모리 handler만 교체하고 새 사용자 경계 조건을 저장한다. 모델 호출/도구 실행/실패 요청 재전송은 하지 않는다. 같은 CLI의 새 사용자 입력만 허용한다. 재시작 후에도 동일 주소·홈·대화·실패 경계를 보존한다. 사용자는 CLI 입력창 복귀를 확인해야 하며 미완료 도구 이력은 여전히 거절될 수 있다.

제어 연결이 미확인 상태라면 마지막 busy 관측값만으로 relay 재연결을 막지 않는다. 살아 있는 daemon 요청은 중단하지 않고 재연결 후 실제 상태를 다시 확인한다. 앱의 Codex 실행 설정 등 기존 변경은 이번 수정 범위에 포함하지 않는다.

검증: `TestProbeQuotaFailureRecovery`는 정상 A 요청 → 4% 조회 → 다음 요청 B 자동 선택, A 429 → checkpoint 재시작 → 명시적 복구 → 기존 입력 차단 → 새 입력 B 성공 및 upstream 호출 횟수를 합성 서버로 검사한다. `DirectProxyCheck`는 복구 ACK와 stale busy 재연결을 검사한다. 실제 사용자의 최초 upstream 실패 원인은 해당 요청의 진단 없이는 확정할 수 없다.
