# ADR 0073: 선택한 연결의 세션 삭제

- 상태: accepted (전체 합성 검증 통과)
- 날짜: 2026-09-23
- 관련: ADR 0048, 0055, 0058, 0070, 0072

## 배경과 선택지

실패한 연결이 목록과 5개 연결 용량을 계속 차지한다. 기존 `proxy-stop --new-session`은 모든 연결이 대기 상태여야 하며 서비스 전체를 종료하므로 다른 개발 작업이 진행 중일 때 사용할 수 없다. 사용자는 실패한 세션을 앱에서 삭제할 수 있도록 요청했다.

전체 daemon 종료나 CLI 기록의 재귀 삭제 대신, 선택한 연결만 안전하게 종료하고 목록에서 제거한다. 대화 기록과 설정은 보존한다. 이 기능에서 세션 삭제는 연결 등록 해제를 뜻하며 디스크의 대화 파일 영구 삭제가 아니다.

## 결정

- 앱 연결 선택기 옆에 **세션 삭제**를 표시하고 같은 메뉴 안에서 연결 번호와 삭제 결과를 확인한다. 취소할 수 있으며 해당 CLI를 먼저 종료하도록 안내한다. 계정 로그아웃이나 다른 연결 종료는 하지 않는다.
- `connection_list.can_delete`를 제공하는 프록시에서만 활성화한다. 선택 연결의 상태가 확인되고 메인·보조 HTTP 요청 및 도구 대기가 모두 없을 때만 삭제한다. 실패한 연결과 사용하지 않는 대기 연결 모두 대상이다. 다른 연결의 작업은 삭제를 막지 않는다.
- 제어 명령 `connection_delete`에는 명시적 연결 번호, 확인 당시 CLI 홈과 revision이 필요하다. coordinator가 선택·홈을 확인하고 대상 probe가 mutex 안에서 revision·대기 요청·메인/보조 작업 상태를 다시 검사한 뒤 신규 요청을 동결한다. 숫자 슬롯이 재사용되어도 오래된 확인으로 새 세션을 삭제할 수 없다.
- 도구 실행 중단을 추정하거나 자동 실패 해제를 하지 않는다. 도구 대기가 남았다면 실제 도구 종료를 확인한 뒤 ADR 0048의 명시적 중단 처리가 먼저 필요하다. 진행 요청을 강제로 취소하는 기능은 아니다.
- 대상의 기존 비공개 checkpoint에 `Deleted`를 동기 저장한 후 대상 listener와 모든 handler·사용량 작업이 종료된 것을 확인하고 성공 ACK를 보낸다. 저장 실패는 성공으로 처리하지 않는다. checkpoint의 기존 치명적 저장 오류 정책은 유지되므로 이 오류의 서비스 전체 영향까지 격리하지는 않는다.
- 시작 시 보안·구조 검증을 통과한 삭제 checkpoint는 복구 목록에서 제외한다. 삭제된 연결 번호는 **새 연결**에서 재사용하며 새 CLI 홈과 capability를 발급한다. 이전 JSONL·설정·인증 자료를 복사하거나 수정하지 않고 소유권을 추정 복원하지 않는다. 새 필드를 모르는 구형 helper로의 다운그레이드는 지원하지 않는다.
- 마지막 연결을 삭제하면 빈 연결 1을 준비한다. 중간에 종료돼 모든 checkpoint가 삭제 상태여도 다음 시작에서 빈 연결 1을 준비한다. 준비만으로 모델 요청을 보내지 않는다.
- 사용량 조회 담당은 첫 번째 살아 있는 연결이다. 담당 연결을 삭제하면 해당 worker가 완전히 종료된 후 남은 연결 중 가장 낮은 번호를 승격한다. 기존 공유 사용량·소진 overlay와 다른 연결의 모델 handler·소유권은 유지한다. 승격 시 최신 사용량을 조회하며 다른 연결을 다시 시작하지 않는다. 전환 중 들어온 사용량 조회·계정 변경 알림은 순서대로 새 담당에 전달한다.
- 삭제 결과를 적용할 때 relay와 앱의 선택 프로필·대화·진단을 비운 뒤 남은 연결 또는 새 빈 연결의 상태를 표시한다. 결과가 확인되지 않으면 자동 재전송하지 않는다. 일반 `proxy-stop`은 연결 1이 없어도 전체 종료가 가능하며 `--new-session --connection N`은 명시한 대상만 사용한다.

추가 의존성 없음. 실행 중인 사용자 앱·프록시에 새 빌드를 자동 적용하거나 실제 실패 세션을 개발 검증 과정에서 삭제하지 않는다.

## 검증

- `TestConnectionDeleteIsolationAndReuse`: 실패한 연결 1 삭제 중 다른 연결의 요청 유지, 진행 요청·stale revision 거절, listener 종료와 성공 ACK 전 영속 삭제, 원본 파일 보존, 사용량 담당 승격, 재시작 시 삭제 유지, 빈 번호 재사용·새 capability·오래된 확인 거절 및 모델 무재전송.
- `TestConnectionDeleteLastAndToolGuard`: 도구 대기 중 삭제 거절, 명시적 중단 후 마지막 세션 삭제와 빈 연결 준비, 모델 무호출.
- `DirectProxyCheck`: 다른 연결이 busy인 상태에서 선택 세션 삭제, ACK 대기·중복 제출 방지, 바뀐 CLI 홈의 오래된 확인 거절, 구버전 capability 부재 차단.
- `MenuLayoutCheck`: 세션 삭제 버튼을 포함한 연결 선택기와 5개 계정 화면 및 삭제 확인 화면의 밝은/어두운 렌더링. 확인 화면은 세션 카드 자리에 표시해 전체 메뉴 높이를 유지한다.

전체 검증은 Xcode 환경의 `sh macos/Checks/verify.sh`로 수행한다. 실계정·사용자 연결 삭제 검증과 앱 업데이트 적용은 별개다.

2026-09-23 검증 결과: 신규 삭제 통합 검사와 기존 다중 연결·사용량 회귀 검사를 `go test -race -count=1`로 통과했다. 최종 변경 상태에서 `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer sh macos/Checks/verify.sh` 전체도 통과했다. Go race/vet, CLI 0.155.1 합성 통합, helper·Swift 빌드, 모델·제어 서버·로그인·DirectProxy·UI 검사를 포함한다. 확인 화면 추가 검사에서 발견한 높이 초과를 수정했고, 5개 계정 화면은 620×847, 삭제 확인 화면은 620×827로 밝은/어두운 테마 모두 통과했다. 기존 Swift 캡처·deprecated API 경고는 남아 있다. 실행 중인 사용자 앱·프록시·연결과 기존 JSONL·checkpoint·인증 정보는 변경하지 않았다.
