# ADR 0068: 다른 계정 갱신 중 유효한 인증의 요청 대기 제거

- 상태: accepted
- 날짜: 2026-09-21
- 관련: ADR 0053, 0064, 0065, 0067

## 배경과 선택지

`RequestAccessContext`는 갱신 여부를 확인하기 전에 공통 mutation 잠금을 기다렸다. A 계정이 OAuth 응답을 기다리는 동안, 갱신이 필요 없는 B 계정의 모델·사용량 요청까지 대기했다.

계정별로 갱신을 동시에 실행하면 전체 계정 레코드를 저장하는 Keychain의 갱신 충돌과 프로세스 간 잠금 설계를 바꿔야 한다. 이 변경은 저장·교환의 직렬화를 유지하고 유효한 인증 조회만 먼저 처리한다. 토큰 캐시는 추가하지 않는다.

## 결정

- 갱신 기능이 있는 manager는 mutation 잠금 대기 전에 로컬 조회 잠금 아래 Keychain을 새로 읽고 기존 형식·신원 검증을 수행한다. 로컬 잠금도 기존 channel 기반 취소 가능 잠금으로 변경하고 요청 context를 전달한다. 잠깐의 조회 경합 때문에 다른 계정의 OAuth 완료를 기다리는 mutation 대기로 넘어가지 않으며, 로그인 중 조회 잠금 대기도 취소할 수 있다.
- 요청 슬롯이 이 manager에서 갱신 중이면 기존 mutation 대기로 합류하여 최종 저장 결과를 확인한다. 진행 중인 blocked marker를 성공한 인증으로 해석하지 않는다.
- 그 외 슬롯은 `refresh_blocked`가 없고 만료까지 2분을 초과하여 남았을 때만 저장된 인증과 해당 계정의 이력 소유권을 반환한다. 정확히 2분 남은 인증도 기존 갱신 경로를 따른다. 영속 차단·계정 부재·저장소 오류는 인증 없이 반환한다.
- 갱신이 필요한 요청은 기존 mutation 잠금을 획득한 뒤 Keychain을 다시 읽는다. 잠금 대기 전 읽은 인증으로 교환하거나 저장하지 않는다. 갱신 및 로그인·로그아웃의 직렬화, 프로세스 간 계정 작업 잠금, durable intent와 검증된 갱신의 이력 소유권 유지 정책은 바꾸지 않는다.
- 로그인·로그아웃의 로컬 조회 잠금과 모델/도구 턴의 프로세스 간 activity lease를 유지한다. 인증 반환 이후 dispatch 시점의 신원·이력 재검사도 유지한다. 취소된 호출자에게 인증을 반환하지 않으며 실패 요청을 자동 재전송하지 않는다.

## 결과와 한계

다른 계정의 OAuth 네트워크 대기 때문에 유효한 인증 조회가 지연되지 않는다. Keychain 읽기·쓰기 및 로그인 자체에 의한 로컬 잠금 경합, 여러 계정이 모두 갱신해야 하는 경우의 직렬 대기는 남는다. 갱신이 필요한 경우 사전 조회가 한 번 추가될 수 있다. 외부 의존성·저장 형식 변경은 없다.

## 검증

- `TestRefreshAllowsOtherValidAccount`: A 갱신 성공·실패를 대기시키는 동안 B 인증과 소유권 반환, 무교환·무저장, A의 대기 취소, 완료 후 B 불변.
- `TestRequestAccessFastPathGuards`: 유효 인증, 정확한 갱신 임계값, 영속 차단, 계정 부재, 저장소 실패, 사전 취소.
- `TestRequestAccessFastPathDuringReauthentication`: 재인증 중 대기 취소, 완료 후 새 등록 세대·이력 소유권, 로그아웃 후 이전 인증 재사용 차단.
- `TestProbeOtherAccountDuringRefresh`: 실제 managed 프록시의 메인·보조 요청이 A 갱신 완료 전에 B 인증으로 전송되는지 검증.
- 기존 단일 갱신·실패 영속 차단·취소·activity lease·이력 격리 회귀 검사와 전체 검증 명령 `sh macos/Checks/verify.sh`를 사용한다. 합성 계정만 사용하며 실행 중인 사용자 프록시는 변경하지 않는다.

2026-09-21: 최종 코드로 전체 검증을 통과했다. Go race/vet, 메인·보조 HTTP 통합 검사, 설치 CLI 합성 검사, helper·Swift 빌드 및 UI 검사를 포함한다. 이전 ADR 0067의 미완료 HTTP 취소 검사도 함께 통과했다. 기존 Swift `onChange` deprecation 경고는 남아 있다. 실제 OAuth 서비스의 응답 호환성을 검증한 결과는 아니다.
