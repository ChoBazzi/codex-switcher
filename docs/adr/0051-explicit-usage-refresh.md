# ADR 0051: 프록시의 즉시 사용량 새로고침

- 상태: accepted
- 날짜: 2026-09-11
- 관련: ADR 0046, 0047, 0050

## 결정

사용자 요청으로 앱의 새로고침을 캐시 읽기에서 실제 사용량 조회로 변경한다. 앱은 외부 API를 직접 호출하지 않고 소유 프록시에 `usage_refresh`와 단조 증가 요청 번호를 보낸다. 프록시가 보관한 동일 결과를 UI와 계정 선택 판단에 사용한다. 기존 `usage` 명령은 진단용 캐시 읽기로 유지한다.

- 시작 시 즉시 조회하고, 각 조회 완료 후 60초를 기다려 자동 조회한다. 느린 조회·절전 이후 밀린 주기를 몰아서 실행하지 않는다.
- 수동 요청은 대기 타이머를 깨워 즉시 조회한다. 자동 조회가 이미 진행 중이면 그 조회 결과를 기다리며 추가 조회를 예약하지 않는다. 완료를 기다리는 수동 요청이 이미 있으면 중복을 거절한다.
- 직전 조회 완료 후 5초 이내의 수동 요청은 프록시에서 거절한다. 제한된 요청은 다음 자동 조회 시점을 연장하지 않는다.
- 자동 타이머와 수동 신호가 겹쳐도 하나의 worker만 조회한다. 네트워크 요청 중에는 제어 파이프용 mutex를 잡지 않아 상태 확인·계정 제어가 계속 처리된다.
- 계정 인증 변경 중이거나 조회 중 인증 세대가 바뀌면 해당 결과를 버리는 기존 규칙을 유지한다. 미등록 계정은 외부 조회하지 않는다.
- 요청별 `started`, `finished`, `busy`, `cooldown` 응답을 보낸다. 완료 전에 snapshot을 전달하며 일부 계정 조회 실패/무효화는 성공으로 표시하지 않는다. 조회 실패 시 기존 사용량은 stale로 보존하며 추가 자동 재시도는 하지 않는다. 다음 정기 조회는 계속된다.
- 앱은 해당 요청 번호의 완료 응답으로만 대기를 종료한다. 캐시/다른 요청의 완료를 잘못 성공으로 처리하지 않는다. 잘못된 snapshot·연결 오류도 대기를 종료한다. 제어 응답 대기는 외부 HTTP 제한 20초를 고려해 30초이며, 시간 초과 뒤 자동 재전송은 하지 않는다.

계정 전환 정책과 모델 요청 무재시도 정책은 변경하지 않는다. UI 배치는 그대로이며 버튼 이름과 상태 안내만 실제 조회에 맞춘다. 새로운 의존성은 없다.

## 검증

- `TestProbeManualUsageRefresh`: 합성 fetcher로 초기 조회 합류, 중복/5초 제한의 축소 시간 테스트, 수동 조회 즉시 시작, 느린 조회 중 중복 방지, 완료 기준 타이머 재설정, 실패 시 오래된 값 보존, 종료 검증.
- `TestProbeUsageSingleSource`: 진단용 `usage`는 여전히 외부 조회를 추가하지 않으며 인증 세대 무효화를 유지.
- `DirectProxyCheck`: 실제 합성 파이프로 새 요청/완료 프로토콜, 이전 요청 완료 무시, 중복 클릭 차단, 시간 초과, 잘못된 데이터 및 복구 검증.
- 실사용: 새 앱/helper 재시작 후 자동 조회가 끝나고 5초 이상 지난 상태에서 새로고침. 성공 계정의 마지막 확인 시각이 갱신되고 완료 문구가 표시되는지 확인한다. 값이 동일해도 시각으로 조회를 확인한다. 계정 한도 없이 사용량 API만 호출하며 모델 요청은 만들지 않는다.
