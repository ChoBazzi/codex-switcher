# ADR 0041: Wiki 하네스 기능 격리

- 상태: accepted (앱 실행·빌드 경로 분리 완료)
- 날짜: 2026-09-09
- 관련: ADR 0009, 0033, 0040

## 결정 배경

현재 개발을 사용량 조회와 계정 전환에 집중한다. Wiki는 이후 프로젝트 하네스로 재사용할 수 있으므로 제거 대신 격리한다. 일반 계정 전환에서 Wiki 작성·인계 상태가 UI를 차단하거나 복원될 이유가 없다.

## 결정

- MenuStore에서 TransferStore 생성과 복원을 제거한다. Wiki 인계 버튼·시트·재확인·상태 참조를 제거하며 로그인·로그아웃·계정 선택·앱 종료가 Wiki busy에 의존하지 않는다.
- Swift Package의 앱 타깃에서 TransferStore.swift/TransferBridge.swift를, UI 모델 타깃에서 Transfer.swift를 제외한다. 소스는 보존하지만 계정 전환 앱에 컴파일·링크하지 않는다.
- Wiki 기록·백업·UserDefaults의 미완료 인계 정보·DB 예약은 삭제하거나 자동 변경하지 않는다. 이후 하네스 이관 시 명시적으로 다룬다.
- Go의 checkpoint/wikidraft/handoff 및 기존 exec 인계 명령은 재사용·호환성 보존을 위해 유지한다. 기존 영속 affinity 보안과 인계 데이터 무효화 처리를 무리하게 제거하지 않는다. 따라서 전체 저장소에서 Wiki 의존성을 모두 제거한 것은 아니다.
- 현재 직접 계정 전환은 DirectProxyStore → managed switch-probe로 유지한다. Wiki 코드 호출이나 새 exec 시작을 추가하지 않는다.
- 전용 Swift 인계 검사와 설치된 CLI 인계 통합 검사는 `macos/Checks/verify-wiki.sh`로 분리한다. 기본 verify.sh는 계정 전환 중심이며 Go 전체 단위 회귀 검사는 계속 유지한다.

## 현재/다음 범위

후속 구현: 사용량 기반 선택은 ADR 0042에서 적용했다. 아래 내용은 분리 당시 범위다.

현재는 사용량 60초 조회와 수동 계정 전환이다. 자동 사용량 판단은 이번 변경에 포함하지 않는다. 다음 구현 대상은 최신 사용량에 따른 초기 계정 선택, 한도 소진 시 다음 요청 계정 선택, 수동 선택과 자동 정책의 관계다. 기존 실패 요청 자동 재전송 금지·진행 중 계정 고정·서버 참조 격리를 유지한다. 단일 CLI·텍스트 전용 제한도 그대로다.

## 검증

앱 빌드에서 Transfer 소스 제외, 앱 진입점의 Transfer 참조 부재, 직접 프록시 합성 검사와 기본 검증을 확인한다. 선택적 Wiki 검사는 보존된 소스를 명시적으로 컴파일한다. 화면 레이아웃 재설계는 없으며 기능 제거·연결 분리만 수행한다.
