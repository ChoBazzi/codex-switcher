# ADR 0037: 별도 채팅 런처 철회와 기존 CLI 직접 연결 원칙

- 상태: 런처 결정 철회, 원래 사용 방식 재확정
- 날짜: 2026-09-08
- 관련: ADR 0002, 0022, 0024, 0030

사용자는 기존 Codex CLI 대화형 화면을 그대로 사용한다. 요청은 로컬 프록시를 거쳐 OpenAI로 전달되고 프록시 측 라우터가 계정 선택과 세션별 인증을 관리한다. 메뉴바 앱은 상태·사용량 표시와 수동 전환을 담당한다. 별도 입력창이나 입력마다 exec를 호출하는 런처로 대체하지 않는다.

동의 없이 추가한 chat 명령과 테스트, exec 쓰기 옵션 및 해당 단계의 미검증 custom tool 확장을 철회한다. 기존 exec/resume/Wiki 인계, 계정 관리, 상태 서버, 앱, 등록 진단과 잔여량 정책은 보존한다. exec는 단계별 검증 경로이며 최종 사용자 인터페이스가 아니다.

## 직접 연결에 필요한 구현 경계

- 원본 Codex 설정을 덮어쓰지 않는 프록시 프로필과 loopback 인증을 제공해야 한다. 실제 사용자 설정에는 아직 설치하지 않았다.
- ADR 0022의 exec stdout thread.started 방식은 TUI에 그대로 적용되지 않는다. 직접 CLI에서 신뢰할 수 있는 시작·재개·프로젝트/worktree 정보를 받아 등록하는 연결이 필요하다. HTTP 헤더의 알 수 없는 ID만 보고 새 세션으로 등록하지 않는다.
- 기존 대화는 원래 계정에 고정한다. A의 continuation을 B에 전달하지 않는다. 전환은 새 세션과 검증된 Wiki로 이루어진다.
- 기존 TUI에서 새 세션으로 이동하는 연결 지점을 검증하기 전 화면 유지 전환 완료를 주장하지 않는다. 지원 불가 시 먼저 제약을 알리고 사용자 동의 없이 런처로 대체하지 않는다.
- 인계 준비만으로 모델을 호출하지 않는다. 사용자 입력을 기다리고 실패 요청은 재전송하지 않는다.

## 상태

이번 수정은 잘못된 별도 런처를 제거하고 기존 구현을 보존하는 정정이다. 직접 TUI 프록시 연결과 앱 전환 연동은 아직 미구현이다. 일반 통합 검사 통과는 해당 기능의 완료를 의미하지 않는다.
