# ADR 0045: 실패 후 명시적 수동 계정 전환

- 상태: accepted
- 관련: ADR 0043, 0044

사용자 요청으로 실패 후 다른 계정으로 수동 전환을 허용한다. 진행 중 요청/도구 턴/대기 요청이 있으면 거절하며, 같은 실패 계정으로 재선택해 잠금을 우회하지 않는다. 앱의 기존 수동 버튼도 실패 여부만으로 비활성화하지 않는다. 인증·최신 사용량·5% 조건은 유지한다(사용량을 조회하지 않는 수동 실험 명령은 기존 로컬 인증 검사만 유지).

선택 수락 시 메모리 프록시 핸들러를 새로 만들고 실패 잠금을 초기화한다. 모델 요청·도구 실행·Wiki 작성은 시작하지 않는다. 이전 실패 기록은 성공으로 바꾸지 않는다. 프록시 재시작이나 CLI 재실행을 강제하지 않으며 기존 연결 주소/대화 ID는 유지한다.

전환 후 첫 요청은 마지막 사용자 메시지의 내용 또는 배열 위치가 바뀐 새 입력이어야 한다. 본문 메타데이터 변경·도구 결과만 추가한 기존 턴·동일 요청의 자동 재전송은 probe_recovery_requires_new_input으로 로컬 거절한다. 사용자 경계는 메모리 해시로만 보관하며 원문을 로그에 남기지 않는다. 프록시가 사용자 의도를 완벽하게 판별하는 것은 아니므로 클라이언트가 새로운 user 항목을 생성하는 경우와 사람의 입력을 암호학적으로 구분하지는 못한다.

이전 계정의 현재 턴 reasoning/continuation은 새 계정에 전달하지 않는다. 미완료 도구 쌍·압축 등 기존 파서 제한은 유지한다. 따라서 모든 중단 작업이 같은 대화에서 복구된다는 보장은 없으며, 새 입력으로도 미지원 이력이 있으면 새 대화가 필요하다. 이미 파일 변경이 발생했을 수 있으므로 사용자에게 현재 상태부터 확인하도록 안내한다.

검증: 종료 취소/후행 실패 후 B 선택 무호출, 원래 입력 재전송 차단, 새 입력 성공, 사용자 경계 해시, UI 실패 상태에서 다른 계정 선택 및 busy 차단을 검사한다.
