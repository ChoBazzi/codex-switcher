# ADR 0033: 메뉴바의 명시적 Wiki 인계 제어

- 상태: accepted (읽기 전용 단발 exec 기반 앱 제어)
- 날짜: 2026-09-08
- 관련: ADR 0027, 0028, 0030, 0031, 0032

## 결정

후속 [ADR 0041](0041-isolate-wiki-harness.md)에 따라 이 UI는 앱 실행 및 빌드에서 제외됐다. 소스와 기존 사용자 기록은 보존하며 선택적 하네스 검사로만 유지한다.

2026-09-09: 기본 전환에서 Wiki를 분리하는 [ADR 0040](0040-same-conversation-switch-and-optional-wiki.md)을 채택했다. 아래 내용은 선택적 Wiki 인계 경로의 설명이다. 기본 버튼은 이제 앱 소유 텍스트 전용 프록시에 연결되며 실제 앱 수동 검증은 남아 있다.

앱은 선택된 정상 종료 세션에서 반대 계정의 전환 준비 버튼을 제공한다. 프로젝트 루트를 사용자가 선택하고 helper가 기존 프로젝트/worktree/브랜치 검증을 수행한다. 원본 conversation, helper 경로, 디렉터리와 대상 계정을 작업 시작 시 고정하여 메뉴 선택 변경으로 진행 중 인계 대상이 바뀌지 않는다. 활성·실패·미연결 관측은 신규 전환 시작 조건으로 사용하지 않는다.

기존 Swift 단발 usage 어댑터와 동일하게 shell 없이 명시적 helper 명령을 실행한다. 상태 API의 GET은 계속 관측 전용이다. 상주 쓰기 API/SSE로의 이행은 후속이며 이번에 별도 네트워크 제어 프로토콜이나 외부 의존성을 추가하지 않는다.

1. 사용자가 `Wiki 작성 시작`을 누르면 원본 대화에서 `exec --resume HANDLE --checkpoint`를 한 번 실행한다. 실제 전송부터 검증까지 기존 Go 3분 제한이 적용된다. 앱은 준비 시간을 포함해 240초 외부 보호 제한을 두며 5초 후에도 종료되지 않으면 강제 종료한다.
2. candidate ID는 실패에서도 보존하지만 저장 성공으로 취급하지 않는다. `checkpoint_saved`/`checkpoint_rechecked`의 ID 일치와 backup_saved, 정상 프로세스 종료를 확인한다. 실패 후 재확인은 기존 로컬 검사만 실행하며 모델 요청을 재전송하지 않는다. 원본 대화가 차단됐으면 저장 검사 성공 후에도 기존 prepare 검증이 전환을 거절한다.
3. Wiki 확인 후 사용자가 미해결 작업 없음·최신 Wiki를 확인해야 `handoff prepare`를 실행한다. 대상 사용량 조회는 기존 CLI에서 수행한다. 성공 시 예약 ID를 보관하고 사용자 입력 대기로 표시하며 모델을 시작하지 않는다.
4. 비어 있지 않은 새 입력과 실행 버튼이 있어야 `exec --handoff ID -- INPUT`을 한 번 실행한다. 기존 대화 resume 인수를 전달하지 않으며 Wiki와 새 입력만 대상 세션으로 전달한다. 답변은 해당 전환 화면의 메모리에만 표시한다. 일반 TUI 프로세스를 유지하는 전환은 아니다. 새 단발 실행의 외부 보호 제한은 600초다.
5. 예약 취소는 `handoff cancel`을 실행하고 성공 이벤트가 확인될 때만 UI 예약을 지운다. Wiki 및 기존 대화는 삭제하지 않는다. 소비한 예약은 다시 전송하거나 취소하지 않는다.

## 실패·재시작·출력

- 작업 중 중복 버튼을 차단한다. 화면 닫기는 작업 취소가 아니며 메뉴에서 진행 화면을 다시 열 수 있다. 정상 앱 종료 버튼은 작업 중 비활성화한다.
- helper stdout과 stderr를 별도로 동시에 소비한다. exec의 제어 이벤트는 stderr에서만 읽고, 생성된 stdout을 제어 이벤트로 해석하지 않는다. 비-exec 제어 명령은 stdout의 구조화 이벤트만 사용한다. 원시 stderr는 표시/저장하지 않는다. stdout 1 MiB, 제어 디코딩과 stderr 128 KiB 상한을 적용한다.
- 앱 설정에는 로컬 원본 handle, 프로젝트/helper 경로, 계정 별칭, checkpoint/예약 ID 및 단계만 저장한다. 프롬프트·답변·Wiki·인증 정보는 저장하지 않는다. 앱 재시작은 `결과 미확인`으로 복원하며 자동 명령 실행이 없다.
- 새 `handoff status -C DIR --conversation HANDLE --checkpoint ID`는 원본과 checkpoint가 일치하는 예약을 로컬 DB에서 찾아 absent/pending/consumed를 반환한다. 모델 및 사용량 조회는 없다. 소비된 예약을 성공한 모델 실행으로 해석하지 않는다. 이 조회를 사용자가 눌러 복원하며 준비 명령을 다시 보내 결과를 추정하지 않는다.
- 후보 ID 수신 전 앱 강제 종료 시 이 화면만으로 후보를 복원하지 못한다. CLI 기록 확인이 필요하며 이 경우도 모델 요청을 자동 실행하지 않는다. 인계 준비/실행 중 오류는 결과 미확인으로 두고 상태 조회로 확인한다.

## 검증

Swift 독립 합성 검사로 명령 인수/원본 격리, 빈 입력과 미확인 boundary 차단, 중복 클릭, 실패 Wiki 재확인, 예약 확인/취소, 재시작 무호출, 사용자 문장 비저장 및 실제 합성 subprocess stdout 위조 이벤트 거절을 검사한다. Go 검사로 상태 조회 시 네트워크 무호출, 원본 격리 및 pending/absent/consumed를 검사한다. 기존 설치된 CLI와 합성 upstream 인계 테스트도 실행한다. 실계정 모델 요청은 개발 중 수행하지 않으며 README의 통합 수동 절차로 확인한다.

Lazyweb의 desktop confirmation/progress 참고에서 확인과 실행 중 상태를 분리하는 패턴을 확인했다. 기존 활성 카드 디자인을 유지하고 별도 전환 화면에 단계·명시적 액션·진행 표시를 배치한다.
