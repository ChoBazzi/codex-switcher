# 0009. 다음 세션 Wiki 인계, 사용자 입력 대기 및 자동 재시도 금지

- 상태: accepted
- 날짜: 2026-09-05
- 관련: ADR 0001, 0003, 0004, 0005, 0006의 전환·복구 정책을 갱신한다.

## 결정 배경

사용자는 Wiki 작성 주체를 Codex, CLI 연결을 프록시, 전환 대상을 다음 세션으로 선택했다. 다음 세션은 Wiki를 참조하되 사용자 입력을 기다리고 실패 복구는 모두 자동 재시도하지 않는다. 저장 격리와 helper 독립 운영은 제안 방향을 채택한다.

## 검토한 선택지

1. 같은 요청을 다른 계정으로 재전송하고 자동 재개: 초기 설계였으나 채택하지 않는다.
2. 현재 Codex의 Wiki를 다음 세션에 인계하고 사용자 입력 대기 (선택).
3. 별도 모델로 Wiki 요약: 채택하지 않는다.

## 최종 결정

- 현재 Codex가 잔여량 50%·10%와 수동 전환 시 Wiki를 작성한다. 작성 실패 후 자동 재시도는 없다.
- CLI는 기존 프록시를 통해 요청한다. App Server 제어 구조로의 변경을 확정한 것은 아니다.
- 전환은 원본 세션의 계정을 바꾸는 것이 아니라 다음 세션을 대상 계정에 연결하는 것이다. 원본 continuation 소유권은 유지한다.
- 다음 세션은 사용자가 같은 CLI에서 명시적으로 시작한다. 프록시가 기존 요청을 새 세션으로 위장하지 않으며 원본·대상 관계가 불명확한 새 세션에는 인계 예약을 적용하지 않는다.
- Codex 대화 ID를 재사용하고 인계 정보에는 프로젝트 해시·worktree·브랜치·원본 대화 ID·검증된 checkpoint_id 및 스냅샷·대상 내부 계정 참조를 둔다.
- 인계 정보가 명시적으로 전달된 새 세션만 등록된 인계를 검증하여 연결한다. 인계 정보가 없으면 일반 신규 세션이며 프로젝트에 예약이 하나 있어도 자동으로 가져오지 않는다. 잘못된 인계 정보는 오류로 처리한다.
- 원본 세션별 인계를 새 대화에 한 번만 원자적으로 연결하고 다른 새 대화에서 재사용하지 않는다. 여러 프로젝트의 인계와 Wiki는 독립적이며 대상 계정 한도는 공유하므로 요청 전 가용성을 재확인한다.
- Wiki 작성 지시는 다음 정상 모델 요청 본문에 추가하는 방향으로 검증한다. CLI가 입력 대기 중이면 사용자에게 Wiki 작성 요청을 보내도록 안내한다. 프록시가 별도 모델 요청으로 Codex를 깨우지 않는다.
- Wiki 저장과 대상 계정 확인이 끝나면 준비 상태로 표시하고 사용자 입력을 기다린다. 준비만으로 모델 요청이나 도구 실행을 시작하지 않는다.
- 실패 요청을 같은 계정이나 다른 계정으로 자동 재전송하지 않는다. CLI와 HTTP 라이브러리의 내장 재시도도 검증·차단한다.
- 자동 오류 복구용 재시도는 로그인·토큰 갱신·사용량·Wiki 실패에도 추가하지 않는다. 정기 사용량 조회와 정기 토큰 유지보수는 독립적인 정상 운영 작업으로 유지한다.
- Wiki 저장은 프로젝트·worktree·브랜치·세션으로 격리하고 원자적으로 교체한다.
- Go helper는 UI 없이도 Keychain 접근과 토큰 유지보수·라우팅을 수행한다. 자동 시작과 업데이트는 진행 중인 요청을 재생하지 않도록 설계한다.

## 기술 검증과 미지원 시 동작

Wiki 저장 확인 기준은 ADR 0010의 로컬 검증으로 확정한다. 요청 본문에 Wiki 지시를 추가할 필드, CLI 기록과의 정합성, 원자적 저장 동작, 사용자가 시작한 새 세션의 식별 및 Wiki 참조 연결은 구현 검증 대상이다. 사용자에게 안내할 정확한 새 세션 시작 명령도 지원 버전에서 확인한다. 새 세션/사용자 입력 식별 없이 실패 요청을 새 요청으로 취급하지 않는다.

## 예상되는 결과와 단점

- 자동 복구와 중복 실행의 복잡도를 줄이고 사용자가 재개 시점을 통제한다.
- 일시 오류에도 사용자 개입이 필요할 수 있다.
- Wiki가 오래됐거나 작성할 수 없는 경우 즉시 인계하지 못할 수 있다.
- 동일 CLI 프로세스 유지와 다음 세션 제어는 실증 전 보장하지 않는다.

## 수용 기준

- 합성 upstream 오류에서 자동 재전송은 0회다.
- 전환 준비 후 사용자 입력 전 B의 모델 호출은 0회다.
- 사용자 입력 후 새 세션만 B에 바인딩되고 원본 A 세션 매핑은 유지된다.
- 같은 프로젝트의 여러 세션과 worktree의 Wiki가 서로 덮어쓰이지 않는다.
- 두 프로젝트의 동시 전환에서 서로의 인계를 소비하지 않고 인계 정보 없는 세션은 일반 신규 세션으로 생성된다.
- 동일 인계에 경쟁하는 두 신규 대화 중 하나만 연결되며 잘못된 인계는 일반 신규 세션으로 대체되지 않는다.
- UI 없이 helper 인증·라우팅이 동작하고 업데이트·재시작으로 실패 요청을 재생하지 않는다.
