# 0010. Go helper의 Wiki 로컬 저장 검증

- 상태: accepted
- 날짜: 2026-09-05
- 관련: ADR 0006, 0009

## 결정 배경

Wiki 작성은 현재 Codex가 담당하고 저장 확인은 추가 모델 호출 없이 Go helper가 수행한다. 파일 존재나 수정 시각만으로 이전 파일·다른 세션 파일·작성 중인 파일을 완료로 오인하지 않아야 한다.

## 검토한 선택지

1. 파일 존재 또는 수정 시각만 확인: 이번 작성 요청과 연결할 수 없어 제외.
2. 모델에 내용 검토 요청: 추가 토큰을 소비하고 로컬 저장 완료 확인에 불필요하므로 제외.
3. 작성 요청 ID와 원본·경로·구조를 로컬 검증 (선택).

## 최종 결정

1. helper가 고유 `checkpoint_id`, 원본 프로젝트·worktree·브랜치·세션, 경로와 요청 상태를 등록한다. ID는 인증 비밀값이 아니라 요청 상관관계 식별자다.
2. 작성 지시에 ID와 메타데이터·필수 항목을 포함한다. Codex가 같은 디렉터리의 임시 파일에 완성한 뒤 최종 파일로 원자적으로 교체한다. 기존 유효 스냅샷을 보존한다.
3. helper는 자신의 등록 레코드와 파일의 ID·원본 정보를 대조한다. 경로는 등록된 루트 안의 일반 파일로 제한하고 심볼릭 링크·경로 이탈을 거절한다.
4. 형식 및 목표·변경 사항·결정·TODO 존재를 검사한다. 해당 내용이 없는 경우 명시적인 `없음`을 허용한다. 최대 크기를 제한하고 문서 내용을 코드나 명령으로 실행하지 않는다.
5. 파일 변경 알림은 검증 시작 신호일 뿐 완료 증거가 아니다. 임시 파일이나 부분 저장을 승인하지 않으며 원자적 저장 방식의 실제 CLI 호환성을 검증한다.
6. 검증한 동일 바이트의 해시·시각을 기록하고 인계 스냅샷을 고정한다. 인계가 가리키는 파일은 모델이 읽을 때까지 고정본을 사용하여 확인 이후의 원본 수정과 혼동하지 않는다. 사용자 편집을 반영하려면 로컬 재검증 후 새 스냅샷으로 갱신한다.
7. 저장 검증 상태와 전환 준비 상태를 분리한다. 수동 전환 준비는 안전한 작업 경계와 대상 계정 가용성까지 별도로 확인해야 한다.
8. 실패·취소·시간 초과 시 기존 유효본을 보존하고 자동 작성 재시도 없이 사용자 조치를 기다린다. 종료된 요청의 늦은 파일 저장은 자동으로 준비 상태를 되살리지 않는다.
9. 파일을 관측·검증하는 데 모델 호출은 없다. 작성 지시를 포함한 요청의 실제 전달부터 저장·로컬 검증 완료까지 제한은 3분(180초)이다. CLI 입력 대기는 제외하며 검증이 먼저 끝나면 즉시 완료한다. 파일 크기 한도는 별도로 정한다.
10. 작성·검증 실패 또는 시간 초과 시 사용자가 `저장 상태 재확인` 버튼을 누르면 helper가 같은 checkpoint_id의 현재 파일을 한 번 로컬 검사한다. `POST /control/checkpoints/{checkpointId}/recheck`는 기존 Control API 인증을 사용한다. 모델 호출, 작성 재요청, 3분 타이머 재시작은 없다.
11. 시간 초과 후 늦게 완성된 파일은 수동 재확인으로만 승인 가능하다. 취소·대체·이미 인계에 소비된 요청은 재활성화하지 않는다. 실행 중 검사에 대한 중복 클릭은 합치며 UI에서 검사 중임을 표시한다.
12. 재확인 성공은 저장 검증 성공을 뜻한다. 작업 경계·계정 가용성 검사를 통과해야 전환 준비 완료로 표시하며 사용자 입력 없이 다음 세션 작업을 시작하지 않는다. 재확인 실패 시 사유를 표시하고 이전 유효본과 대기 상태를 유지한다.

## 예상되는 결과와 한계

- 모델 토큰 없이 이번 요청의 저장 결과와 원본 세션을 확인할 수 있다.
- ID와 해시는 요약의 의미적 정확성이나 실제 도구 실행 성공을 증명하지 않는다.
- 원자적 저장 방식과 파일 형식은 Codex가 실제로 따르는지 검증해야 한다. 임의의 수정 파일을 완성본으로 오인하면 안 된다.
- helper 종료 직전 이벤트나 저장 장치 장애까지 완전 복구를 보장하지 않는다. 복구 시 등록 상태와 유효 스냅샷을 대조하고 작성 요청을 재생하지 않는다.

## 수용 기준

- 지시 전달 전 입력 대기에는 제한 시간을 적용하지 않고 전달 후 저장·검증이 180초 내 끝나지 않으면 시간 초과로 처리한다.
- 늦은 파일 저장은 자동 승인하지 않으며 명시적 재확인에서 기존 요청 ID로 검사한다.
- 수동 재확인에는 모델 호출·작성 재요청·대기 타이머 재시작이 없고 연속 클릭은 검사를 중복 실행하지 않는다.
- 취소·대체·인계 사용 완료 요청은 재확인으로 활성화되지 않는다.

- 이전 ID·다른 세션·경로 이탈·부분 파일·필수 항목 누락은 완료로 승인되지 않는다.
- 원자적으로 저장된 올바른 파일은 모델 호출 없이 검증된다.
- 검증 이후 원본 수정에도 인계 대상 바이트는 고정되며 편집 반영은 로컬 재검증을 요구한다.
- 파일 저장이 성공해도 진행 중이거나 결과가 불명확한 도구 실행이 있으면 수동 전환 준비가 완료되지 않는다.
- 실패·취소·시간 초과 후 늦은 저장이나 helper 재시작이 작성 재시도 또는 자동 전환을 발생시키지 않는다.
