# ADR 0044: 완료 이벤트 전달과 요청 잠금 순서

- 상태: accepted
- 관련: ADR 0043

## 재현

도구 모드에서 response.completed를 CLI에 전달한 뒤에도 upstream EOF를 기다리는 동안 busy가 유지됐다. 같은 세션의 후속 요청이 409 probe_request_in_progress로 거절됐고, 첫 연결이 취소되면 이후 probe_previous_request_failed로 차단됐다. 합성 재현으로 확인했으며 실제 사용자 연결이 취소된 원인까지 확정한 것은 아니다.

## 결정

- 도구 모드에서 SSE 완료 프레임 및 이후 프레임을 최대 1 MiB로 보류한다. 이전 프레임은 그대로 스트리밍한다. 정상 EOF와 전체 응답 검증 후 턴 상태·계정 소유 정보를 갱신하고 완료 프레임을 원문 그대로 전송한다. 완료 이후 실패 이벤트·부분 프레임·읽기 오류에서는 성공 이벤트를 내보내지 않는다.
- 완료 이벤트 관측 후 요청 정리 중인 동일 세션에 한해 후속 요청 최대 1개를 30초까지 대기시킨다. 인증·대화 ID를 확인하고 앞 요청의 defer 정리가 끝난 뒤 실패 상태를 다시 검사한다. 실패한 선행 요청은 복구하지 않으며 대기 요청도 upstream으로 보내지 않는다. 대기 취소·시간 초과·다른 세션·추가 대기 요청은 실행하지 않는다.
- 대기 요청의 원문 본문 해시가 직전 요청과 같으면 probe_duplicate_followup으로 거절한다. 본문이나 해시는 로그에 남기지 않는다. 이는 새로 받은 후속 요청의 직렬화이며 실패 요청의 자동 재전송이 아니다.
- probe_request_finished를 defer에서 정확히 한 번 남겨 panic/연결 취소에서도 진단이 누락되지 않게 한다. 알려진 고정 오류를 유지하고 불명확한 중단은 probe_request_interrupted, 클라이언트 취소는 probe_client_canceled로 기록한다. 원문 오류·토큰·대화는 기록하지 않는다.
- 기존 실패 차단·도구 턴 중 계정 고정·5% 정책은 유지한다. 텍스트 실험 및 영속 프록시의 기존 전달 정책은 변경하지 않는다.

## 검증

TestProbeCompletionOverlap: upstream이 완료 이벤트 후 연결 종료를 지연하도록 구성한다. 정상 종료 후 후속 요청 1회 전달, 첫 연결 취소 및 후행 오류 시 후속 요청 미전송, 동일 본문 거절, 대기 요청 취소와 진단을 검증한다. TestProbeTerminalGate는 분할/CRLF 프레임의 보류·원문 보존을 검증한다. 실제 CLI 합성 도구 왕복과 전체 검증도 수행한다.
