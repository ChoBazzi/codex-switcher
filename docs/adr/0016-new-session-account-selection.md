# ADR 0016: 신규 세션 계정 선택의 내부 경계

- 상태: accepted
- 날짜: 2026-09-06
- 관련: ADR 0004, 0005, 0009, 0015

## 배경과 선택지

실제 사용량 조회는 사용자 환경에서 성공했다. HTTP 헤더만 보고 자동 등록하면 resume/재시도를 새 대화로 오인할 수 있다. 따라서 검증된 신규 대화 이벤트에서만 등록하는 내부 모듈을 먼저 구현한다.

## 결정

일반 신규 세션의 90% 사용 차단 규칙은 ADR 0036으로 대체되었다. 현재는 최신 정상 사용량과 인증이 유효하고 잔여량이 양수이면 허용한다. 명시적 인계 대상의 여유량 검증은 유지한다.

- 기본 `internal/routing.New`는 메모리 `handoff.Store`를 단일 저장소로 소유한다. ADR 0017의 `NewPersistent`는 이를 SQLite 단일 저장소로 대체한다.
- 신뢰된 브리지가 일반 신규 대화와 사용자 입력을 확인한 뒤에만 `Register`를 호출한다. resume/인계 예약 소비에는 사용하지 않는다. `Resolve`는 등록·계정 재선택을 하지 않으며 프로젝트·worktree·브랜치·세션 전체가 일치해야 한다.
- 신규 세션은 소진 임계값 미만인 계정 중 두 구간 최소 잔여율이 가장 높은 계정을 선택한다. 동률이면 a. 기본 임계값은 90%, 생성 시 80~95%로 지정한다. 정확히 임계값에 도달한 계정도 신규 선택에서 제외한다.
- 미확인·오래된 수치(2분), 조회 오류, 일시 제한, 서버 allowed/limit_reached 미확인 또는 거절, 이미 지난 reset_at은 제외한다. 리셋 시각 경과만으로 충전을 추정하지 않고 정상 조회를 기다린다. 선택 및 요청 직전 인증도 읽기 전용 재확인한다.
- 기존 세션에는 사전 선택 임계값을 적용하지 않는다. 잔여량이 양수이고 최신 사용량·인증이 유효하면 원래 계정으로 해석한다. 사용 불가 시 오류로 멈추며 다른 계정으로 바꾸지 않는다. 사용량 조회 장애 시 기존 요청도 보수적으로 차단하되 매핑은 유지한다.
- 사용량은 복사해 보관한다. 이전 시도의 뒤늦은 결과가 최신 실패를 덮지 못하게 하며 동시 등록은 단일 승자만 허용한다. 선택과 로컬 인증 확인은 모델 요청/재시도가 아니다.

## 단계 범위와 단점

- 프로덕션 CLI에는 아직 연결하지 않는다. 신뢰된 신규 대화 판별, continuation 소유권 검증, SQLite 및 실패 상태 영속화가 필요하다. 임의 HTTP 요청으로 Register를 호출하거나 알 수 없는 continuation을 신규 세션으로 바꾸면 안 된다.
- ADR 0004의 SQLite/14일 정리 정책은 유지한다. 이번 메모리 모듈은 이를 대체하지 않으며 재시작 연속성을 보장하지 않는다.
- Wiki 인계 예약, 수동/자동 전환 준비, 제어 API 및 앱 표시는 후속 구현이다. 원본 세션 매핑은 변경하지 않는다.
- 외부 의존성 추가 없음. 합성 테스트로 신규 선택/기존 고정, 미확인 수치·인증 만료, 동시 등록 및 프록시 429 후 재전송 차단을 검증한다.

## 검증

```sh
go test -race -count=1 ./internal/routing
```

실제 인증이나 모델을 호출하지 않는다. 프록시 통합 테스트는 loopback 포트를 사용한다.
