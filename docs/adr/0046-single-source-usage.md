# ADR 0046: 프록시 단일 사용량 조회

- 상태: accepted
- 관련: ADR 0042, 0045

후속 [ADR 0051](0051-explicit-usage-refresh.md)이 아래 캐시 전용 새로고침 결정을 대체한다. 앱은 프록시에 즉시 외부 조회를 요청하며 다음 자동 조회는 완료 후 60초로 재설정한다. 단일 데이터 원천과 인증 세대 무효화는 유지한다.

후속 [ADR 0050](0050-account-grid-and-cache-refresh-feedback.md)에서 캐시 새로고침의 진행/완료/실패 피드백을 추가했다. 외부 조회 주기는 변경하지 않는다.

후속 [ADR 0047](0047-five-account-capacity.md)에서 조회 슬롯을 A~E로 확장했다. 계정 작업 종료 후 로컬 인증 확인으로 등록 여부는 즉시 반영하지만 외부 사용량 조회는 아래 60초 주기를 유지한다.

앱 관리 프록시가 시작 시 및 60초 간격으로 A/B 사용량을 조회한다. missed tick은 모아서 재실행하지 않는다. 전환 판단에 저장한 동일 snapshot을 기존 stdout 제어 파이프로 앱에 전달한다. 앱의 UsageBridge.read 호출과 별도 조회 타이머는 제거한다. 기존 UsageBridge 코드는 보조 검사/호환성을 위해 남지만 앱의 주 실행 경로에서 호출하지 않는다. 별도로 실행하는 CLI usage 명령까지 금지하거나 통합하지는 않는다.

앱 새로고침은 프록시의 캐시를 읽는 usage 제어 명령이다. 외부 호출을 추가하지 않는다. 캐시는 조회 시각으로 stale 처리하며 프록시 종료/제어 연결 미확인 시 앱의 값도 stale 표시한다. 오래된 프로세스 이벤트는 기존 generation 검사로 무시한다.

로그인/로그아웃 시작·완료 시 해당 슬롯 캐시를 즉시 무효화한다. 작업 중이거나 캐시 세대가 바뀐 경우 이미 진행 중이던 조회 결과를 반영하지 않는다. 세대가 바뀌면 Monitor의 과거값 보존 캐시도 다음 주기에서 재생성한다. 새 계정의 조회 실패가 이전 계정 사용량을 복원하지 않게 한다. 작업 후 최신 상태는 다음 정기 조회까지 최대 약 60초와 조회 소요 시간이 필요하며 버튼 연타로 조회를 추가하지 않는다.

자동 모드에서는 미등록/만료 계정이 있어도 프록시를 시작하여 계정 상태를 앱에 전달한다. 사용 가능한 계정이 없으면 모델 요청은 기존 quota admission에서 거절한다. 플래그 없는 수동 실험의 시작 인증 조건은 유지한다.

검증: TestProbeUsageSingleSource는 합성 fetcher로 초기 계정당 1회 조회, cache 읽기 5회 무호출, 계정 변경 중 in-flight 결과 무효화, 종료를 검사한다. Swift 검사는 파이프 사용량 수신·종료 stale callback을 확인하고 verify.sh는 앱의 독립 조회 호출/타이머 재도입을 검사한다. 기본 전체 Go 검사와 앱 빌드도 유지한다.
