# ADR 0060: 제어 relay 단절 시 앱 생존과 명시적 재연결

- 상태: accepted
- 날짜: 2026-09-20
- 관련: ADR 0054, 0057, 0059

## 배경

relay가 종료된 직후, EOF 처리 Task가 main actor에서 실행되기 전에 상태 조회나 제어 명령이 실행될 수 있다. 닫힌 파이프에 대한 `FileHandle.write`는 오류를 던지기 전에 기본 `SIGPIPE` 동작으로 앱을 종료한다. 프로세스 실행 여부 사전 확인만으로는 확인과 쓰기 사이의 경쟁을 막을 수 없다.

## 결정과 대안

- relay 시작 전에 앱 소유 제어 파이프의 쓰기 descriptor에 Darwin `F_SETNOSIGPIPE`를 설정한다. 설정 실패 시 relay를 시작하지 않는다.
- 전역 `SIGPIPE` 무시는 선택하지 않는다. 앱의 다른 I/O와 자식 프로세스의 신호 처리를 바꾸지 않고 해당 파이프의 `EPIPE`만 기존 오류 처리 경로로 전달한다. 외부 의존성은 추가하지 않는다.
- 전송 실패 시 앱 소유 relay만 분리하고 연결 generation을 교체한다. 준비·작업 중·명령 대기·사용량 조회 상태를 초기화하고 이전 사용량을 미확인으로 표시한다. 이전 relay의 지연된 이벤트와 타이머는 무시한다.
- daemon과 CLI 기록은 변경하지 않는다. 자동 재연결·명령 재전송·모델 요청을 하지 않으며, 사용자의 명시적 재연결 후 실제 상태를 다시 받는다. 전송 중 오류는 서버 처리 여부를 보장하지 않으므로 전환 성공으로 표시하지 않는다.
- 종료 명령 전송 실패는 정상 종료로 간주하지 않고 실패 callback을 한 번만 전달한다. 성공 ACK와 EOF를 확인하는 기존 종료 계약은 유지한다.

## 검증

`macos/Checks/DirectProxyCheck.swift`에 기본 SIGPIPE 동작을 사용하는 별도 검사 프로세스와 합성 relay를 둔다. 닫힌 제어 입력에 상태 조회·계정 선택·사용량 새로고침·종료를 보내도 앱이 생존하고 상태를 무효화하는지, 자동 재전송 없이 명시적으로 재연결할 수 있는지 검사한다. 실제 계정·Keychain·사용자 daemon·모델 호출은 사용하지 않는다. 기존 정상 제어·로그인·종료 검사는 그대로 유지한다.
