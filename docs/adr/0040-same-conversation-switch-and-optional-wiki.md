# ADR 0040: 같은 대화 계정 전환과 선택적 Wiki

- 상태: accepted (텍스트 전용 앱 제어 구현, 실제 앱 수동 검증 대기)
- 날짜: 2026-09-09
- 관련: ADR 0004, 0009, 0033, 0038, 0039

후속 [ADR 0041](0041-isolate-wiki-harness.md): Wiki 인계는 앱에서 제거하고 별도 보존 코드·선택 검사로 격리했다. 아래 선택적 Wiki 버튼 유지 설명은 해당 ADR로 대체한다. 계정 전환·실패 안전성 정책은 유지한다.

## 근거

사용자가 텍스트 전용 switch-probe에서 동일 Codex TUI의 A 응답 이후 B로 선택을 변경하고 이전 문맥을 이어가는 동작이 정상이라고 보고했다. 합성 CLI exec/resume 검사에서도 이전 메시지·assistant phase 보존과 합성 A/B 인증 변경을 확인했다. 도구·reasoning·압축·오류 복구·다중 세션의 성공 증거는 아니다.

계정 인증과 로컬 대화 기록을 구분한다. 계정 변경이 반드시 대화 유실을 뜻한다는 전제로 Wiki를 강제하지 않는다. 컨텍스트 윈도우나 서버 캐시가 계정 간 공유된다고 주장하지 않는다.

## 결정

- stock Codex CLI → 앱이 관리하는 로컬 프록시 → 선택 계정 구조를 유지한다. 앱이나 helper가 입력창을 대신하거나 일반 대화를 별도 exec로 실행하지 않는다.
- 기본 전환 목표는 정상 요청 완료 후 같은 대화의 다음 요청 계정을 변경하는 것이다. 우선 텍스트 전용 검증 범위를 명시한다.
- 수동 계정 선택은 Wiki 작성·새 세션 발급·추가 모델 호출을 요구하지 않는다. 다음 사용자 입력을 기다린다.
- Wiki는 선택적 요약·백업·새 대화 인계로 분리한다. 수동 전환 및 50%/10% 경계가 자동 Wiki 작성의 필수 조건이라는 기존 기본 전환 설계는 철회한다. 기존 Wiki·예약·기록은 삭제하거나 자동 변환하지 않는다.
- A의 서버 continuation 식별자를 B에 전달하지 않는다. 현재 실험의 message id 정규화·도구 선언 제외·불투명 이력 차단은 유지한다.
- 진행 중 요청의 계정은 변경하지 않으며 바쁜 경우 전환을 거절한다. HTTP 응답 종료가 일반 도구 작업 전체 완료를 뜻하지 않으므로 텍스트 전용 제한을 유지한다.
- 실패 요청 자동 재전송은 금지한다. 계정 변경으로 실패 상태를 해제하지 않는다. 자동 한도 전환은 이번 성공 보고만으로 완료로 간주하지 않는다.

## 앱 제어 계약

- 기존 status-server와 모델 프록시를 구별한다. 앱은 `switch-probe --allow-live --managed` 자식도 실행한다. 모델 HTTP는 private profile 비밀값과 loopback으로 보호한다. 제어는 별도 HTTP API 대신 자식에게 상속한 stdin/stdout 파이프를 사용한다. 공개 제어 포트·추가 제어 토큰·외부 의존성이 필요 없으며 다른 서버에 연결하지 않는다.
- 선택 명령은 대상 슬롯과 관측 revision을 전달한다. 프로세스별 파이프와 UI 세대 값이 인스턴스를 식별하고, 서버는 첫 대화 하나만 허용한다. 요청 시작·종료·선택 시 revision이 증가하므로 오래된 상태·진행 중 요청·실패 상태를 거절한다. managed 모드는 JSON만 허용하며 터미널용 raw a/b는 받지 않는다. 쓰기 명령을 자동 재시도하지 않는다.
- 선택 수락과 실제 B 요청 성공을 구분한다. 선택 계정·처리 계정·진행 중 여부·차단 상태는 프록시 확인 결과로 제공한다. 응답 유실은 조회로 확인하며 성공으로 추정하지 않는다.
- 최초 연결은 실험과 같은 단일 대화 범위다. 여러 프로젝트/세션을 하나의 전역 슬롯으로 일괄 전환하지 않는다.
- 기본 전환은 기존 TransferStore의 Wiki 작성 흐름을 호출하지 않는다. Wiki 인계는 별도 명시적 작업으로 유지한다.

## 구현 상태와 수용 기준

앱의 기본 A/B 전환 버튼은 DirectProxyStore를 통해 해당 자식 프록시를 제어한다. 현재 계정·처리 중 상태는 프록시 확인 결과를 표시한다. 기존 파란 활성 배경을 재사용하고 화면 재디자인은 하지 않는다. 사용량이 오래됐거나 부족한 계정·로그인/인계 중에는 버튼을 차단한다. 명령 직전 서버는 대상 인증을 재확인하며 선택 수락이 모델 가용성 보장은 아니다.

앱 시작 시 두 서버를 각각 실행한다. 미등록/만료 A/B로 모델 프록시가 종료되면 로그인 후 사용자가 재시작한다. 준비 제한 15초, 상태 조회 1초, 4초 이상 상태 미확인 시 전환 차단, 선택 ACK 제한 3초다. 결과 미확인 상태에서 자동 재전송하지 않는다. 앱 종료는 소유 파이프 EOF로 프록시를 정지하고 필요 시 소유 자식에만 종료 신호를 보낸다. 모델 요청 중 재시작·정상 앱 종료·계정 변경 UI는 비활성화한다.

`Codex CLI 연결 명령 복사`는 임시 CODEX_HOME을 지정하는 명령만 복사한다. 앱이 CLI를 실행하거나 프롬프트를 전송하지 않는다. 사용자가 원하는 프로젝트 터미널에서 직접 실행한다. 프록시 재시작 시 새 프로필·새 CLI가 필요하며 기존 임시 대화 기록은 삭제하지 않는다. 여러 CLI를 연결하거나 일반 도구 작업을 지원하는 것으로 표시하지 않는다.

Wiki 기능은 기존 exec 관측 세션에 대한 별도 선택적 인계 버튼으로 남긴다. native CLI 세션을 기존 exec 인계 기록으로 위장하지 않는다. 프록시의 현재 상태와 기존 exec 상태 조회는 독립적이다.

Go 합성 검사: managed JSON 선택·오래된 revision 거절·raw 명령 거절·선택 무호출·EOF 종료 및 busy/failed 선택 금지. Swift 합성 자식 검사: 준비·선택 ACK·중복 선택 방지·종료 후 늦은 이벤트 격리. 실제 같은 TUI에서 앱 버튼 A→B와 문맥 보존은 별도 수동 검증한다. 일반 도구·압축과 다중 세션은 추가 검증 전 지원으로 표시하지 않는다.
