# ADR 0070: 여러 메인 CLI 대화의 독립 연결

2026-09-23: [ADR 0073](0073-explicit-connection-session-deletion.md)은 선택한 대기·실패 세션의 삭제와 빈 연결 번호 재사용을 추가한다. 삭제 checkpoint는 복구에서 제외하고, 사용량 조회 담당 연결을 삭제하면 남은 연결로 담당을 이전한다. 아래 연결 제거 미지원 및 연결 1 고정 조회 설명은 해당 결정을 따른다.

## 배경과 선택지

기존 프록시는 한 루트 대화에 바인딩됐다. 같은 홈의 재개 선택창에서 다른 대화를 실행하면 기존 루트와 충돌했다. 단순히 대화 ID 검사를 완화하면 계정·도구·암호화 이력과 실패 잠금이 섞인다. 연결마다 별도 daemon을 실행하면 사용량 중복 조회와 계정 작업 잠금 충돌이 생긴다.

하나의 daemon이 최대 5개의 독립 probe를 관리한다. 계정 최대 5개와 연결 최대 5개는 별도 한도이며 같은 계정으로 여러 연결을 사용할 수 있다. 원격·다중 사용자 기능이나 외부 의존성을 추가하지 않는다.

## 결정

- 연결마다 별도의 loopback HTTP 주소, 로컬 capability, CODEX_HOME, 루트·보조 대화 registry, handler, 계정 선택, 실패 잠금, checkpoint와 암호화 이력 소유권을 갖는다. 한 연결에는 한 루트만 허용한다. 다른 루트나 다른 연결의 capability를 수락하지 않는다.
- 기존 연결 1은 runtime 루트의 주소·홈·checkpoint를 유지한다. 추가 연결은 고정된 `connection-2`~`connection-5` 비공개 디렉터리를 사용한다. 디렉터리 생성과 부모 fsync를 실행한 뒤 시작하며, 이 디렉터리가 복구 대상 목록이다. 시작에 실패한 디렉터리도 다음 시작에서 복구 대상으로 검사한다. 손상·포트 충돌을 새 연결로 우회하지 않는다. 기존 홈·대화 기록은 삭제하지 않는다.
- 시작 시 기존 연결을 모두 복구한다. 선택 화면은 연결 1에서 시작하며, 앱의 제어 relay만 재연결하면 daemon의 현재 선택을 유지한다. 새 연결은 새 CLI 대화를 위한 빈 홈이다. 기존 홈의 대화나 사용자 설정을 자동으로 복사하지 않는다.
- 하나의 계정 manager를 공유해 OAuth 갱신과 신원 확인을 직렬화한다. daemon 안에서 활동 잠금의 참조 수를 세어 여러 연결의 동시 턴을 허용한다. 마지막 모델·도구 턴이 끝날 때까지 기존 OS 배타 잠금을 유지하므로 외부 로그인·로그아웃은 모든 연결과 배타적이다.
- 연결 1만 기존 주기로 사용량을 조회한다. 모든 연결은 동기 공유 캐시에서 동일한 최신 관측을 읽는다. 계정 변경 무효화도 같은 캐시에 즉시 반영한다. 별도 poller나 지연 전달 큐를 만들지 않는다. 인증·사용량 장애와 계정 한도는 해당 계정을 쓰는 연결에 공통 영향을 줄 수 있다.
- coordinator는 연결별 이벤트·진단을 보관하고 선택된 연결의 상세 상태와 전체 연결 목록을 앱에 보낸다. 선택 변경 시 relay와 앱에서 이전 연결의 상태·진단 캐시를 비운다. 인증 진행 상태는 여전히 재연결 캐시에 남기지 않는다. 연결 ID를 명시한 잘못된 제어 명령은 기본 연결로 대체하지 않는다. ID 없는 구버전 명령은 연결 1만 대상으로 한다.
- 앱은 연결 선택·추가, 선택한 연결의 계정 전환·복구·설정 편집을 제공한다. 연결 선택은 모델 요청을 만들거나 다른 연결을 중단하지 않는다. 계정 등록·로그아웃 화면은 모든 연결의 busy를 확인하고 서버 측 활동 잠금이 최종적으로 보호한다. 연결 기능을 알리지 않는 구버전 daemon에는 추가 제어를 보내지 않는다.
- 연결된 대화의 재개 명령에는 검증한 UUID를 지정해 임의 대화 선택을 피한다. 대화 ID는 로컬 제어 상태에만 전달하고 진단 복사에 넣지 않는다. 설정 편집기의 기존 초안·외부 수정 충돌 보호를 유지한다.
- 전체 종료는 먼저 모든 probe의 신규 요청을 동결한다. 하나라도 모델·도구 작업 중이면 모두 동결을 해제하고 그 완료 후 거절한다. 모두 준비되면 OS 활동 잠금을 잡아 계정 작업과 경합을 확인한 뒤 전체를 종료한다. 모든 probe가 종료된 다음 최종 ACK를 전송한다. 일부 연결만 먼저 종료하지 않는다.
- `proxy-stop --new-session --connection N`은 모든 연결이 idle일 때 서비스를 종료하며 N번 연결만 retired로 저장한다. 다음 시작에서 해당 연결은 새 홈·주소를 만든다. 다른 연결의 복구 정보와 모든 과거 홈은 보존한다. N을 생략하면 1이다. 추가 연결 번호는 daemon의 다중 연결 지원과 등록 목록을 확인한 다음에만 전달한다.

## 결과와 한계

여러 터미널에서 독립된 루트 대화를 동시에 사용할 수 있다. 한 대화의 모델 실패는 다른 대화의 실패 잠금을 바꾸지 않으며 자동 재전송은 계속 금지한다. 같은 연결 명령을 여러 루트에 공유하거나 같은 대화를 두 터미널에서 동시에 조작하는 기능은 아니다. `/new`·`/fork`를 기존 연결에 그대로 보내는 제한은 유지한다.

프로세스·사용량 조회·인증 저장소는 공유한다. daemon 자체의 종료, 시작·checkpoint의 치명적 실패까지 연결별로 가용성을 보장하지는 않는다. 연결 제거·이름 변경·기존 대화 가져오기는 이번 범위가 아니다. 슬롯을 새 대화에 다시 쓰려면 명시적인 maintenance 명령으로 기록을 보존하고 교체한다. 활성 연결만 선택적으로 강제 종료하는 기능은 제공하지 않는다.

## 검증

- `TestMultiProbeConcurrentIsolationAndRestart`: 서로 다른 계정의 동시 루트 요청, 독립 capability·루트 검사, 실패 무재전송과 다른 연결의 계속 실행, 선택되지 않은 연결의 활동에 따른 전체 종료 거절과 동결 해제, 주소·홈·키 복구 및 재시작 무호출.
- `TestMultiProbeCapacityAndQuotaInvalidation`: 5개 한도, 단일 계정별 사용량 조회, 계정 변경 무효화의 다른 연결 적용.
- `TestSharedTurnsReferenceCount`, `TestMultiProbeAccountMutationBlocksShutdown`: 중복 Close 방어, 마지막 턴까지 유지되는 활동 잠금, 계정 작업 중 종료 거절.
- `TestMultiProbeUnsafeDirectory`, `TestServiceConnectionSwitchClearsCache`: 비공개 디렉터리 검사와 relay 캐시 격리.
- `DirectProxyCheck`: 연결 추가·선택, 대상이 명시된 계정 제어, 전체 busy, 대화 ID가 지정된 재개, 다른 연결의 오래된 상태 무시, 종료 거절, 구버전 동작 유지.
- 전체 검증: `sh macos/Checks/verify.sh`. 실제 계정·실행 중인 사용자 daemon을 변경하지 않는 합성 검사다.
