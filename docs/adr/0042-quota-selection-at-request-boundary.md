# ADR 0042: 요청 경계에서 사용량 기반 계정 선택

2026-09-22: [ADR 0071](0071-explicit-usage-limit-failover.md)이 출력 전 명시적 사용량 소진에 한해 자동 재전송 금지와 현재 턴 계정 고정의 예외를 추가한다. 일반 오류·부분 출력·암호화 압축에는 기존 제한을 유지한다.

- 상태: accepted
- 날짜: 2026-09-09
- 관련: ADR 0040, 0041

후속 ADR 0046에서 앱의 별도 사용량 조회를 제거하고 프록시 snapshot 전달로 통합했다. 아래 두 조회 주체 설명은 당시 구현 기록이다.

## 전환 기준 변경

사용자 요청으로 잔여량 전환 기준을 0%에서 **5% 이하**로 변경했다. 최초 선택 및 자동·수동 전환 대상은 최신 유효 잔여량이 **5% 초과**인 계정이다. 수동 선택도 5% 이하가 되면 다음 요청에서 자동 정책을 적용한다. 둘 다 5% 이하이면 요청을 차단하고 자동 재전송하지 않는다. 기존 계정 카드의 A/B 전환 버튼을 유지하며 활성 조건도 동일하게 변경한다. 아래 한도 소진 표현에는 이 예비 잔여량 기준 도달을 포함한다.

앱이 실행하는 managed switch-probe에 `--auto`를 지정한다. 플래그 없는 수동 실험은 유지한다. Wiki·affinity DB·모델 호출 없이 기존 usage Monitor로 즉시 및 60초마다 두 계정을 조회한다. 기존 앱 표시용 조회도 유지하므로 현재는 조회 주체가 두 개다. 조회 통합은 후속 작업이다.

첫 요청에는 최신 유효 잔여량이 큰 계정을 선택한다(동률 A). 이후에는 현재 계정을 유지하며, 한도 소진이 확인된 경우에만 다음 요청을 다른 유효 계정으로 보낸다. 수동 선택도 첫 자동 선택보다 우선하며 이후 같은 유지 정책을 따른다. 현재 요청 중에는 조회 결과가 바뀌어도 계정을 변경하지 않는다.

최종 성공 조회가 2분 이상 지났거나 조회 실패·미확인 필드가 있으면 사용 가능하다고 추정하지 않는다. 현재 계정이 불명확하면 임의 전환 없이 `probe_usage_unavailable`, 대안이 없으면 `probe_no_available_account`로 요청을 거절한다. 첫 조회 완료 전 요청도 거절할 수 있다. 이 로컬 거절은 모델로 보내지 않으며 자동 재전송하지 않는다. 사용자는 이후 새로운 입력을 명시적으로 보낼 수 있다.

실제 프록시 요청 실패 후의 세션 차단과 자동 재전송 금지는 그대로다. 응답 도중 한도 오류를 받은 요청을 다른 계정에서 이어 실행하지 않는다. A의 서버 continuation 참조를 B에 넘기지 않는 텍스트 전용 정규화와 단일 CLI 제한도 유지한다. 시작 시 두 계정의 로컬 인증 확인은 여전히 필요하다.

검증: TestProbeQuotaSelection은 초기 선택·동률·유지·양방향 전환·둘 다 소진·오래된/누락/실패한 조회를 합성 데이터로 검사한다. 기존 managed 제어·요청 중 선택 금지·실패 후 선택 금지 회귀 검사도 유지한다. 실계정 자동 전환 검증은 별도로 필요하다.
