# ADR 0029: 영속 인계 예약과 신규 세션의 원자적 연결

- 상태: accepted (내부 저장소/라우터/프로세스 바인딩 단계)
- 날짜: 2026-09-07
- 관련: ADR 0009, 0017, 0022, 0028

## 결정

메모리 인계와 별도로 실제 영속 라우터용 인계 예약을 SQLite 스키마 2에 추가한다. 기존 0/1 저장소는 트랜잭션으로 테이블/인덱스를 생성하며 세션·응답 소유권은 변경하지 않는다. 이전 바이너리는 스키마 2를 지원하지 않으므로 자동 다운그레이드를 하지 않는다.

예약에는 원본 세션, 대상 a/b, checkpoint ID·SHA256, 생성 시각 및 소비한 새 세션만 저장한다. Wiki 본문이나 인증정보는 DB에 넣지 않는다. 스냅샷 고정 파일의 영속 보존은 CLI 연결 단계에서 완료해야 하며 이 단계의 API는 신뢰된 caller가 그 수명을 보장한다.

PrepareHandoff는 원본 ready·안전 경계, 다른 대상 계정, 검증한 Wiki 원본/해시, 대상의 최신 사용량과 로컬 인증을 확인한다. 원본별 대기 예약은 하나만 허용한다. 준비만으로 새 세션을 생성하거나 모델을 호출하지 않는다.

대기 중 원본 Begin은 거절하여 예약 뒤 원본 작업과 Wiki가 어긋나지 않게 한다. 원본 매핑/ready 상태 자체는 변경하지 않는다. 원본 작업을 다시 하려면 정확한 source와 예약 ID로 CancelHandoff를 호출해야 하며 삭제된 예약은 재사용할 수 없다. 소비된 예약의 취소는 금지한다. 이 보류/취소를 CLI UI에 연결하기 전에는 실제 사용자 예약 명령을 노출하지 않는다.

BindHandoff는 명시적 사용자 입력, 새 origin과 원본의 프로젝트/worktree/브랜치 일치, 예약 미소비, 고정 스냅샷 ID·해시, 대상 계정 가용성을 다시 확인한다. 신규 세션 INSERT와 예약 소비 UPDATE를 하나의 트랜잭션으로 수행한다. 경쟁 시 한 개만 성공하고 원본 continuation은 복사하지 않는다. 가용성 실패를 다른 계정이나 일반 신규 세션으로 대체하지 않는다. 소비 후 실행 실패에도 예약을 되돌리거나 모델 요청을 재전송하지 않는다.

clisession.NewHandoff는 사용자 입력과 명시적 예약으로만 생성하며, 해당 CLI 프로세스의 검증된 thread.started에서 연결한다. HTTP 헤더로 등록하지 않고 원본 thread ID는 대상 프로세스에서 거절한다. 이 바인딩 자체는 Wiki를 프롬프트에 넣지 않는다. 별도 CLI 연결에서 원본 메타데이터/continuation ID를 제외한 Wiki 본문을 사용자 입력과 함께 전달해야 한다.

원본 세션이 14일 GC로 제거되면 연결된 예약도 cascade 제거한다. 알 수 없게 된 예약을 추정 복구하지 않는다. 예약 취소는 예약 메타데이터만 삭제하며 별도 스냅샷 정리는 후속 작업이다.

## 검증과 남은 범위

후속 ADR 0030에서 CLI 예약/취소/exec --handoff와 고정 Wiki 파일, 재확인 소비 상태 검사를 연결했다. 아래 미연결 목록은 이 ADR 최초 구현 시점 기준이다.

합성 SQLite/라우터/바인딩 테스트로 스키마1 마이그레이션, 재시작 복원, 원본 보류/취소, 안전 경계·ID·worktree 검사, 경쟁 단일 승자, 소비 후 재사용/취소 차단, 대상 한도 재검사, 스냅샷 변조 거절, 원본 계정 및 continuation 격리를 검증한다. 준비 중 모델 요청 경로는 없으며 신규 등록은 사용자 입력과 시작 이벤트 뒤에만 발생한다.

실제 CLI 예약/취소/exec --handoff 명령, pinned Wiki 파일 수명과 소비 상태를 로컬 재확인에 연동, 메뉴바 UI, 실제 두 계정 왕복 테스트는 아직 미연결이다. 이 단계만으로 사용자 계정 전환이 완료됐다고 표시하지 않는다. 외부 의존성 추가 없음.
