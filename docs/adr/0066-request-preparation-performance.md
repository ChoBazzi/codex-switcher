# ADR 0066: 긴 대화의 요청 파싱과 checkpoint 비교 비용 감소

- 상태: accepted
- 날짜: 2026-09-21
- 관련: ADR 0043, 0055, 0061, 0063, 0064, 0065

## 배경과 선택지

루트 도구 요청은 사용자 경계, native 압축 항목, 이력 검증, 현재 턴 소유권 판정을 위해 전체 입력 배열을 네 번 디코딩했다. 메시지 하나를 검사할 때도 임시 JSON 요청을 만들어 텍스트 파서로 다시 디코딩·인코딩했다. 보조 요청도 경계 검사와 이력 검증이 같은 배열을 따로 읽었다.

checkpoint는 이미 이전 성공 저장과 동일하면 쓰기와 fsync를 생략한다. 그러나 같은 상태인지 확인하기 위해 매번 최대 1,024개 소유권 배열을 만들고 별도 비교용 map을 할당했다. 실제 저장 횟수를 줄이려고 상태 전이를 합치거나 비동기 저장하면 crash 시 전송·완료 여부를 잃을 수 있으므로 채택하지 않는다.

## 결정

- 요청마다 `probeToolInput`에 최상위 필드와 입력 배열을 한 번 디코딩하고 루트·보조에서 재사용한다. 사용자 경계는 정규화 전에, 현재 턴 소유권 요구는 검증·과거 reasoning 제거 후의 결과에서 계산한다. native 압축 원본 항목은 변형하지 않고 dispatch 직전 재검사에 사용한다.
- 메시지 검증의 기존 계약을 `probeTextMessage`로 공유해 메시지별 임시 요청 직렬화와 재파싱을 제거한다. 허용 필드, phase, 텍스트 형식, 인라인 이미지 제한, call ID 치환 및 계정·reasoning 소유권 검사는 유지한다.
- 파싱 결과는 해당 요청에서만 사용한다. 정규화가 item ID를 변경하므로 한 번 사용한 결과를 다른 요청에 캐시하지 않는다. 본문·이미지·사용자 텍스트를 checkpoint나 새 로그에 보관하지 않는다. 공통 HTTP 프록시의 JSON 유효성 검사와 크기 제한도 그대로 둔다.
- checkpoint는 마지막 성공 저장의 소유권 배열을 현재 소유권 registry에 직접 대조한다. 실제 변화가 있을 때만 저장할 배열을 만든다. 순서에 무관하게 key·슬롯·인증 해시와 나머지 모든 복구 필드를 비교한다. 마지막 snapshot은 유일한 key를 가진 내부 registry에서 만든 성공 저장본만 사용한다. 디스크에서 읽은 자료를 곧바로 이 비교의 근거로 사용하지 않는다.
- 초기·요청 진입·전송 전·완료·실패·계정 변경의 기존 동기 저장 시점을 유지한다. 저장 성공 전 캐시 갱신, 저장 실패 우회, 자동 요청 재전송은 추가하지 않는다. 파일 형식과 외부 의존성 변경 없음.

## 측정

macOS arm64, Apple M5 Pro, 같은 머신·Go 환경에서 `-race` 없이 3회 측정한 중앙값이다. 기준 구현은 `188c410`이며 같은 합성 입력과 처리 단계를 사용했다. 네트워크·Keychain·모델 응답·디스크 fsync는 요청 준비 벤치마크에 포함하지 않는다. B/op는 누적 할당량이며 최대 상주 메모리가 아니다.

| 합성 조건 | 변경 전 | 변경 후 | 시간 감소 | 할당량 전 → 후 |
| --- | ---: | ---: | ---: | ---: |
| 완료된 도구 쌍 1,000개 + 메시지, 약 1.17 MB | 16.12 ms | 8.63 ms | 46% | 25.96 → 16.16 MB/op |
| 2 MiB 합성 이미지의 base64 도구 결과, 약 2.80 MB 요청 | 18.80 ms | 13.52 ms | 28% | 30.87 → 21.88 MB/op |
| 소유권 1,024개, 변경 없는 checkpoint 비교 | 54.50 µs | 10.74 µs | 80% | 197,264 → 576 B/op |

checkpoint 측정은 비교 함수 비용만 포함한다. 이전 방식에서 비교 전 소유권 배열을 만드는 비용과 실제 디스크 쓰기는 제외했다. 이 최적화가 fsync 자체나 모델 응답을 위 비율만큼 빠르게 만든다는 뜻은 아니다.

현재 구현의 재현 명령:

```sh
go test ./cmd/switcher-helper -run '^$' \
  -bench 'BenchmarkProbePreparation|BenchmarkProbeCheckpointCompare' -benchmem -count=3
```

입력 생성은 측정 시간 밖에서 수행한다. 준비 단계는 원문 SHA-256, 사용자 경계 계산, 압축 항목 추출, 검증·정규화, 소유권 요구 판정을 포함한다. 이미지는 실제 사용자 파일이 아닌 0으로 채운 합성 바이트이며 모델의 이미지 유효성 검증과는 별개다. 성능 수치를 CI의 시간 임계값으로 강제하지 않는다.

## 검증

- `TestProbeParsedInputOwnershipMetadata`: 과거 reasoning 제거, 원본 compact 보존, 현재 턴 도구 소유권 요구와 사용자 경계 유지.
- `TestProbeParsedInputRejectsInvalidShapes`: JSON·메시지·서버 참조·미승인 opaque 이력의 기존 거절 분류.
- `TestProbeCheckpointRegistryComparison`: 기존 비교 구현과 대조하여 모든 scalar 복구 필드, 소유권·인증 변화, 순서, 보조 대화 및 최초 저장 검사.
- 기존 `TestProbeCheckpointStatusDoesNotWrite`, 저장 실패·강제 종료 복구 검사, 루트·보조 계정 격리 및 이미지 CLI 통합 검사로 실제 경로를 검증한다.
- 전체 검증: `sh macos/Checks/verify.sh`. 실행 중인 사용자 앱·daemon이나 실제 계정을 사용하지 않는다.

2026-09-21: 전체 Go race/vet, helper·Swift 빌드, 설치 CLI 합성 통합 검사와 UI 검사를 통과했다. 실행 중인 사용자 프록시는 교체하지 않았다.
