# ADR 0032: 관측 전용 CLI 세션 상태와 앱 연결

- 상태: accepted (읽기 전용 단발 exec 및 앱 연결)
- 날짜: 2026-09-07
- 관련: ADR 0001, 0022, 0030, 0031

## 결정

기존 CLI 실행별 프록시와 affinity의 소유권은 변경하지 않는다. 별도 `status-server`가 관측용 메타데이터만 읽어 `GET /control/sessions`로 제공한다. 이 서버는 실제 모델 프록시를 대체하는 상주 데몬이 아니며, 종료되어도 실행 중인 CLI를 취소하지 않는다.

- exec의 신뢰된 thread.started 등록 이후 conversation handle, 프로젝트/worktree/브랜치 해시, A/B 별칭, 상태와 시각만 기록한다. 원본 thread ID, 경로, 프롬프트, 응답, 인증 토큰 및 실제 계정 ID는 기록하지 않는다.
- private Application Support `com.bazzi.codex-switcher/session-status/<conversation>.json`에 0600 원자 교체로 저장한다. 실행 중 1초 heartbeat를 갱신한다. 이 파일은 라우팅 승인이나 재개 가능성의 근거가 아니다.
- 등록 후 `waiting`, proxy BeforeAttempt에서 `active`, 정상 단발 종료는 `closed`, 실행/후처리 실패는 `failed`로 표시한다. active는 해당 exec가 요청을 수행 중이라는 관측이며 upstream이 이미 성공적으로 수신했다는 보장은 아니다. 종료 후 입력 대기를 살아 있는 CLI로 표시하지 않는다.
- 5초 이상 heartbeat가 끊긴 waiting/active는 `disconnected`로 반환한다. 강제 종료 시 active 파일이 남아도 활성 표시가 영구 유지되지 않는다. 관측 쓰기 실패는 모델 요청의 실패나 재전송을 유발하지 않는다.
- 마지막 24시간, 살아 있는 active/waiting 우선 및 최신 변경 순 최대 64개를 제공한다. 디렉터리 4096개 초과 또는 잘못된 파일은 보수적으로 API 실패 처리한다.
- 상태 서버 시작 시와 이후 매시간 관측 파일을 정리한다. heartbeat와 상태 변경 시각 모두 14일을 초과한 유휴 파일만 삭제한다. 정확히 14일인 파일, 미래 시각, 최신 heartbeat가 있는 장기 실행은 보존한다. 강제 종료로 남은 active/waiting도 14일 초과 유휴이면 정리한다. 24시간 표시 범위와 14일 디스크 보존은 별개다.
- 정리는 128개 단위로 순회하여 조회 제한을 넘은 과거 파일도 처리한다. 파일 교체와 삭제는 공통 로컬 파일 잠금으로 직렬화하며 삭제 직전에 검증된 최신 JSON을 읽는다. GET은 계속 읽기 전용이고, 정리와 겹쳐 사라진 항목은 건너뛴다. 잘못된 파일은 삭제하지 않고 정리 오류 코드만 출력한다. Wiki, 대화 본문 및 affinity DB는 이 정리의 대상이 아니다. 새로운 의존성은 없다.
- 디렉터리 소유자/권한과 파일의 소유자·단일 링크·일반 파일·크기를 검증한다. 읽기에서 symlink를 따르지 않는다. 같은 OS 사용자가 악의적으로 상태를 변조하는 것을 완전히 방어하는 신뢰 경계는 아니다.

## 제어 API 및 앱

- `status-server --port 8766`은 127.0.0.1에만 바인딩한다. 최소 32자 환경 변수 `SWITCHER_CONTROL_TOKEN`으로 인증한다. Authorization 중복, 브라우저 Origin, GET 이외 요청을 거절한다. 토큰은 저장·출력하지 않는다.
- ADR 0034부터 앱은 기본적으로 자체 상태 서버를 시작한다. `--external-status` 모드에서는 같은 환경 변수와 선택적 `SWITCHER_CONTROL_URL`(기본 http://127.0.0.1:8766)을 읽는다. 임의 원격 주소/사용자 정보/쿼리/프래그먼트는 허용하지 않는다. ephemeral URLSession, 리다이렉트 금지, 2초 제한과 128 KiB 상한을 적용한다.
- 이번 단계는 SSE 대신 1초 polling을 사용한다. 최초 API 계약·연결 끊김을 검증하는 중간 단계이며, 최종 독립 helper/SSE 아키텍처는 유지한다. 실패 즉시 재시도하지 않고 다음 정규 조회에서만 갱신한다. 모델 요청은 하지 않는다.
- API 실패 시 즉시 활성 강조를 해제하고, 응답이 멈춰도 3초 후 연결 끊김 처리한다. 마지막 선택 세션 정보는 참고용으로 남기되 활성 상태로 표시하지 않는다.
- 기본 선택은 최신 active, 없으면 최신 변경 세션이다. 사용자가 특정 conversation을 선택하면 해당 세션을 유지한다. 실제 활성 상태만 기존 파란 배경을 사용한다. 프로젝트/worktree/브랜치는 짧은 해시로 표시한다.

## 검증 및 한계

합성 테스트로 생명주기·종료/실패·heartbeat 만료·다중 관측·API 인증/메서드·빈 목록·잘못된 파일·동시 읽기/쓰기를 검사한다. Swift 모델 검증은 상태 파싱, 활성 만료, 종료 상태와 잘못된 별칭 거절을 검사한다. 실제 CLI→앱 UI 경로는 사용자 수동 검증이 필요하다.

14일 경계, 정상 heartbeat와 강제 종료 잔류, 미래 시각, symlink 거절, 동시 게시/정리, 4096개 초과 기록 정리 후 조회 복구 및 활성 세션 우선 보존을 합성 테스트로 검사한다. 14일 이내 파일만으로 4096개 제한을 넘으면 조회 제한은 여전히 적용된다. 상태 서버가 꺼져 있는 동안에는 정리하지 않고 다음 시작 시 수행한다.

세션 저장소가 여러 세션을 표시할 수 있다는 것이 현재 exec 프록시의 모든 동시 실행 제약을 해소했다는 뜻은 아니다. 기존 affinity 잠금/CLI 기능 범위는 그대로다. 이전 바이너리로 수행한 실행은 소급 복원하지 않는다. ADR 0033에서 별도 단발 명령 어댑터로 Wiki 전환/취소/재확인 버튼을 연결했다. 일반 TUI 연결은 후속이다.
