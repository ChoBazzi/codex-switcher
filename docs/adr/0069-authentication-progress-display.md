# ADR 0069: 인증 대기·갱신 및 취소 후 마무리 상태 표시

- 상태: accepted
- 날짜: 2026-09-21
- 관련: ADR 0062, 0067, 0068

## 배경과 선택지

인증 대기와 토큰 갱신은 모델 요청 전에 수행된다. 이미 시작한 갱신은 요청이 취소되어도 저장까지 마쳐야 하지만 앱은 일반적인 작업 중 상태만 표시했다.

요청마다 새 이벤트와 네트워크 polling을 추가하는 대신, 기존 1초 간격 제어 상태 조회에 메모리 상태를 포함한다. 진행 상태는 실행 권한이나 성공 여부를 결정하는 자료로 사용하지 않는다.

## 결정

- 계정 manager는 인증 접근 호출의 대기 개수와 시작한 갱신을 슬롯별로 집계한다. 고정된 최대 5개 슬롯 외의 식별자는 받지 않는다. 대기는 로컬 조회·잠금 획득·인증 확인 중인 호출을 포함한다. 유효한 인증이 즉시 반환되면 짧은 상태는 앱 조회 사이에 종료될 수 있다.
- 영속 갱신 의도 저장 직전에 대기에서 갱신으로 전환하고, 교환·신원 확인·Keychain 저장이 끝나 호출이 반환될 때 해제한다. 호출자의 context가 취소된 동안에는 취소 후 안전한 마무리 상태를 보여 준다. 저장 중에도 갱신 표시를 유지하며, 모든 오류 반환 경로에서 상태를 정리한다. 이전 호출의 늦은 정리가 다음 갱신 상태를 지우지 않도록 갱신 단위를 구분한다.
- 상태 전용 mutex를 사용하여 OAuth·Keychain 잠금을 기다리지 않고 조회한다. 외부 callback, 요청별 상태 goroutine, 추가 OAuth·모델·사용량 요청은 만들지 않는다. 취소 후 안전한 저장, 실패 영속 차단, 다른 계정의 유효 인증 접근 및 자동 재전송 금지 정책은 그대로 유지한다.
- 기존 `probe_state` 및 같은 상태 형식의 응답에 `authentication` 배열을 추가한다. 각 원소는 슬롯, 대기 개수, 갱신 여부, 갱신을 시작한 호출자의 취소 여부만 담는다. 토큰·실제 계정/대화 식별자·본문·로컬 경로·오류 원문은 담지 않는다. 상태 기능이 없으면 null, 지원하지만 진행 중인 인증이 없으면 빈 배열을 보낸다.
- 진행 상태는 checkpoint·영속 로그에 기록하지 않는다. relay 재연결 캐시에서도 해당 필드는 제외해 완료된 갱신을 되살리지 않고 다음 상태 조회를 기다린다. 기존 busy·실패·계정 선택·종료 승인 조건은 바꾸지 않는다.
- 앱은 기존 relay 세대 검사와 유효한 상태 이벤트 처리 후 인증 배열을 별도로 검증한다. 슬롯 허용 목록·중복·개수·자료형·취소/갱신 관계가 잘못됐거나 구버전에서 생략되면 미확인으로 처리한다. 상태 미확인·연결 종료 시 인증 표시를 비운다.
- 메인 세션 카드에 인증 대기·토큰 갱신·취소 후 마무리를 표시하고 도움말을 제공한다. 상태·진단 화면에는 취소 후 저장을 기다리는 이유와 자동 재전송 금지를 표시한다. 진단 복사도 검증된 슬롯과 고정된 안내만 사용한다. 메인·보조·사용량 호출을 슬롯별로 합산하므로 개별 대화 진행 단계로 추정하지 않는다.

## 결과와 한계

기존 조회 주기 내에서 현재 인증 작업을 확인할 수 있다. 아주 짧은 상태는 표시되지 않을 수 있고, helper 밖에서 수행하는 로그인 자체의 진행률을 추가로 추적하지 않는다. 소요 시간이나 완료율은 추정하지 않는다. 새 의존성·제어 프로토콜 버전 변경은 없다.

## 검증

- `TestAuthenticationProgressThroughCommit`: 갱신·동시 대기·대기 취소·시작 요청 취소·저장 중 조회·완료 후 제거 및 토큰 보존.
- `TestAuthenticationProgressClearsOnFailure`, `TestAuthenticationProgressLateCleanup`: 오류 경로 정리와 이전 갱신 정리의 다음 갱신 보호.
- `TestProbeStatusAvailableDuringRefresh`, `TestProbeCanceledRefreshProgress`: 실제 HTTP 프록시의 갱신 상태, 취소 후 종료 거절·작업 유지, 완료 후 상태 해제와 모델 무전송.
- `TestServiceAuthenticationCacheIsTransient`: relay 캐시에 인증 진행 상태를 남기지 않으면서 busy는 유지.
- `DirectProxyCheck`: 대기·갱신·취소 안내, 비밀값 비노출, 구버전·잘못된 입력·연결 종료 처리.
- `MenuLayoutCheck`: 5개 계정의 인증 활동과 기존 오류를 함께 표시하는 밝은/어두운 진단 화면.
- 전체 검증 명령: `sh macos/Checks/verify.sh`. 합성 계정만 사용하고 실행 중인 사용자 앱·프록시는 변경하지 않는다.

2026-09-21: 계정 관리자 전체 race 검사, 포트 없는 인증 상태·relay 캐시·진단 검사, `go vet ./...`, Swift 빌드, `DirectProxyCheck` 및 밝은/어두운 UI 검사를 통과했다. 5개 계정 인증 활동과 오류를 포함한 진단 화면은 620×483으로 렌더링되며 밝은 화면을 직접 확인했다. 전체 검증의 권한 확대 실행은 자동 승인 검토의 `409 probe_previous_request_failed` 오류로 실행되지 않아 신규 HTTP 통합 검사는 대기 상태다. 기존 Swift `onChange` deprecation 경고는 유지한다.

2026-09-21 후속: 권한 확대 실행이 승인되어 `sh macos/Checks/verify.sh` 전체 검증을 통과했다. Go race/vet, 신규 HTTP 인증 진행 상태·취소 후 마무리 검사, 설치 CLI 합성 검사, helper·Swift 빌드와 UI 검사를 완료하여 위 통합 검증의 대기 상태를 해소했다. 실제 계정 및 실행 중인 사용자 앱·프록시는 변경하지 않았다.
