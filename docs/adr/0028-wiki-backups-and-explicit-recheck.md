# ADR 0028: Wiki 전역 백업과 명시적 로컬 재확인

- 상태: accepted (CLI 연결, UI/전환 미포함)
- 날짜: 2026-09-07
- 관련: ADR 0006, 0010, 0027

## 결정

Wiki 생성 종료 후 동일 대화의 private CLI home에 `wiki-candidate.md`와 `wiki-request.json`을 보존한다. 등록 정보에는 checkpoint ID, origin, 원래 deadline 및 상태가 있으며 원문은 후보 파일에만 둔다. 새 작성 요청은 이전 등록을 대체하고, 명시적 재확인은 최신 등록의 정확한 ID만 허용한다. 임시 생성 디렉터리는 제거하지만 후보는 남긴다. 기존 프로젝트 유효 Wiki와 후보 파일은 별개다. 프로세스 강제 종료로 후보가 보존되지 않으면 자동 복구하지 않는다.

사용자는 `checkpoint recheck -C DIRECTORY --conversation HANDLE --id CHECKPOINT_ID`로 후보를 한 번 로컬 검증한다. 대화 잠금·프로젝트/worktree/브랜치·원본 세션을 확인한다. 이 명령은 모델 실행, Keychain, 사용량 조회, affinity 상태 변경을 호출하지 않는다. 실패한 대화의 Wiki 검사만 가능하며 대화의 ready 플래그는 변경하지 않는다.

실패·타임아웃·검증된 요청만 재검사하며 취소·미전달·대체 요청은 거절한다. 원래 deadline을 변경하지 않는다. 후보 파일을 수동으로 수정한 경우에도 등록된 메타데이터·형식·크기를 만족해야 한다. symlink/비정규 파일은 거절한다. 검증 성공은 저장 검증일 뿐 미확인 모델/도구 결과의 성공이나 전환 허용을 의미하지 않는다. 현재 인계 소비 기능은 없으며 이후 소비 상태와 연결할 때 재확인을 금지해야 한다.

검증된 Wiki는 프로젝트 최신본 게시 후 `~/.codex/switcher/projects/<project>/<worktree>/<branch>/<source-session>/snapshots.json`에도 보관한다. 세션별 최근 3개 스냅샷을 최신순으로 원자 교체하는 단일 묶음이다. 각 스냅샷은 검증 바이트·해시·메타데이터·검증 시각을 가진다. ID와 해시가 모두 같은 재확인은 중복 저장하지 않는다. 기존 묶음의 무결성/원본 검증 실패 시 덮어쓰지 않는다. 새 묶음 게시 전 오래된 개별 파일을 삭제하지 않는다. 최대 3개 밖의 항목은 교체된 묶음에서 제외되며 별도의 자동 복구 저장소는 없다.

프로젝트 게시와 전역 백업은 서로 다른 파일시스템일 수 있어 단일 트랜잭션이 아니다. 백업 실패 시 로컬 최신본은 남을 수 있지만 전체 성공 이벤트는 출력하지 않는다. 사용자는 같은 요청의 로컬 재확인으로 다시 저장을 시도할 수 있다. 자동 재시도는 없다.

`checkpoint_candidate`는 요청 ID를 제공할 뿐 생성/검증 성공을 뜻하지 않는다. `checkpoint_saved` 또는 `checkpoint_rechecked`의 backup_saved=true가 두 저장 단계 성공을 뜻한다. switch_ready는 여전히 false이며 사용자 입력 전에 새 계정이나 모델을 호출하지 않는다.

## 검증 및 후속 작업

합성 테스트로 최근 3개 유지·중복 제외·해시 불일치 보존·세션 격리·symlink 거절, 불완전 후보 거절, 수정 후보 재검증, 타임아웃 후 원래 deadline 유지, 취소/대체/다른 ID 거절, 검사 이후에도 실패 대화 재개 불가를 검증한다. 실계정과 실제 사용자 백업은 개발 테스트에서 접근/변경하지 않는다. 인계 예약·소비·안전 경계 및 대상 계정 검사, UI 재확인 버튼은 후속 작업이다. 새 외부 의존성 없음.
