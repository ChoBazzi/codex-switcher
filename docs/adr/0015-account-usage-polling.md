# ADR 0015: 계정별 읽기 전용 사용량 조회

- 상태: accepted
- 날짜: 2026-09-06

## 배경

두 계정의 브라우저 등록 및 단일 계정 실요청 검증 후, 메뉴바 표시와 라우팅 판단의 입력인 사용량 조회가 필요하다. ADR 0005의 60초 조회/수동 갱신, ADR 0006의 미확인 값 보수 처리 원칙을 따른다.

## 선택지

1. 매번 모델을 호출하여 응답 헤더로 사용량을 추정: 불필요한 모델 요청이며 유휴 계정 조회에 부적합.
2. 공식 CLI의 화면/프로세스 출력을 파싱: UI 변화에 취약하고 별도 세션이 필요.
3. helper가 저장된 인증으로 사용량 메타데이터만 조회: 선택. backend의 비공개 스키마 의존성을 명시한다.

## 결정

- Go `internal/usage`가 고정 HTTPS `https://chatgpt.com/backend-api/wham/usage`를 GET으로 한 번 호출한다. 설치된 Codex 0.153.4 바이너리에서 `/wham/usage`와 구간 필드 이름을 확인했으나 공개 API 보장으로 취급하지 않는다. 실제 사용자 응답을 fixture로 저장하지 않는다.
- `rate_limit.primary_window` 및 `secondary_window`의 `used_percent`, `limit_window_seconds`, `reset_at`와 `allowed`, `limit_reached`만 정규화한다. 추가 모델별 한도·크레딧 등은 추정하지 않는다. 0과 누락을 구분하며 누락/null은 unknown, 타입 오류·범위 오류·과대 본문은 안전한 오류 코드로 처리한다.
- 두 구간 잔여율의 최솟값은 **관측용**이다. `state: ok`는 조회 수치가 확인되었다는 뜻이지 모델 호출 가능성/라우팅 승인을 보장하지 않는다. `limit_reached`는 서버 명시 값으로만 표시한다. 429만으로 소진을 추론하지 않는다.
- 계정 토큰은 기존 Keychain `Manager.Access`로 읽고 실제 식별자를 헤더에만 넣는다. 자동 토큰 갱신·재인증·저장 변경은 하지 않는다. 읽기는 로그인 작업의 장시간 잠금을 잡지 않으므로 watch 중 사용자의 재인증을 막지 않는다.
- 요청마다 새 HTTP/1 연결, 환경 프록시 미사용, redirect 미추적, 최대 20초, 본문 최대 128 KiB. 실패 즉시 재시도 없음. 헤더·본문·원본 네트워크 오류를 출력하지 않는다.
- `usage [--watch] [a|b]`는 기본 두 계정을 독립 조회한다. watch는 즉시 1회 후 60초 고정 주기이며 중첩/밀린 주기 따라잡기를 하지 않는다. 사용자는 단발 명령을 재실행하여 수동 갱신한다. 모델 요청 재시도와 별개로 다음 정규 메타데이터 조회는 수행한다.
- 실패한 계정은 watch 프로세스 메모리의 이전 성공 데이터·성공 시각을 보존하고 stale 처리한다. 다른 계정의 성공은 반영한다. 소비자는 마지막 성공에서 2분 경과 시에도 stale 처리한다. 없는 계정은 수치 없이 not_registered. 프로세스를 새로 실행하면 이전 표본은 복원하지 않는다.

## 단계 경계와 결과

- 이 단계는 라이브러리 및 진단 CLI까지다. SwiftUI/상주 helper 제어 API/현재 활성 계정 표시/실제 라우팅 변경은 포함하지 않는다.
- `checkpoint_level`은 stateless 관측값이며 이벤트가 아니다. ADR 0006의 세션·계정·한도 구간별 영속 중복 방지, 두 경계 동시 진입 병합 및 실제 Codex Wiki 요청은 후속 연동에서 구현한다. stale/unknown 표본을 Wiki 요청이나 전환 근거로 사용하지 않는다.
- 외부 Go 의존성 추가 없음. 합성 서버로 스키마, 단일 시도, 인증, 429/오류, redirect 차단, 계정 독립성, stale 보존 및 타이머를 검증한다. 실사용 backend 응답 호환성은 사용자 조회로 별도 확인한다.
- 공개 계약이 없는 endpoint 변경과 만료된 인증은 조회 실패로 표시한다. 원본 응답을 저장해 복구하거나 모델을 호출하여 보완하지 않는다.
