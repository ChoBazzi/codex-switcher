# ADR 0034: 앱 소유 상태 서버 자동 실행

- 상태: accepted
- 날짜: 2026-09-08
- 관련: ADR 0032, 0033

## 결정

2026-09-09 추가: [ADR 0040](0040-same-conversation-switch-and-optional-wiki.md)에 따라 앱은 상태 서버 외에 텍스트 전용 모델 프록시 자식도 별도로 소유한다. 기존 상태 서버의 포트·제어 API를 모델 프록시로 재사용하지 않는다.

실사용 앱은 --helper 경로가 있으면 `status-server --managed --port 0`을 shell 없이 자식 프로세스로 시작한다. 수동 재시작은 기존 소유 서버를 종료한 뒤 새 인스턴스를 만든다. 데모는 서버를 시작하지 않는다.

사용자 요청에 따라 개발용 helper 선택/변경 버튼과 선택창 코드를 제거한다. 현재 개발 실행에서는 --helper로 경로를 지정하며, 미지정 시 실행 인수 안내만 표시한다. 상태 서버 재시작 버튼과 계정 전환 준비 버튼은 유지한다. 앱 번들에 helper를 내장하는 작업은 후속이다.

앱이 Security.framework의 시스템 난수로 256비트 제어 토큰을 만들고 해당 자식의 환경 변수에만 전달한다. 매 실행 새 토큰을 사용하며 저장하거나 출력하지 않는다. Go 서버는 127.0.0.1:0에 bind하여 OS가 빈 포트를 배정하도록 한다. 준비 후 stdout에 event=status_server_ready와 port만 반환한다. 앱은 4 KiB 제한으로 준비 메시지를 읽고 인증된 상태 GET과 스키마 검증까지 통과해야 연결한다. 준비 제한은 5초다.

앱은 소유 서버의 stdin 파이프 쓰기 끝을 보유한다. 정상 종료·helper 변경·서버 재시작 시 이를 닫으며, 앱 강제 종료 때도 OS가 파이프를 닫아 서버에 EOF를 전달한다. 서버는 managed 모드에서 EOF를 종료 신호로 처리한다. 정상 종료 후에도 살아 있으면 앱은 2초 뒤 SIGTERM, 4초 뒤 SIGKILL을 소유 Process에만 보낸다. 다른 서버나 CLI, 프록시, 인계 작업은 종료하지 않는다.

종료 관측 시 앱은 활성 강조를 해제하고 재시작 버튼을 제공한다. 자동 서버 재실행과 모델 요청 재전송은 하지 않는다. 이전 연결의 늦은 응답은 세대 번호 및 bridge 동일성 검증으로 버려 새 연결 상태를 덮어쓰지 않는다.

`--external-status`를 지정한 경우에만 기존 환경 변수 기반 외부 상태 서버에 연결한다. 이 경우 서버를 시작·종료하지 않는다. 기본 자동 모드는 이전에 export된 토큰/주소를 재사용하지 않는다. 기존 수동 서버가 떠 있어도 별도 빈 포트를 쓰며 자동으로 종료하지 않는다.

## 검증

Go 합성 테스트: 임시 HOME에서 port 0 준비 이벤트, 인증 유무, 토큰 비노출, 소유 stdin EOF 종료 확인.

Swift 합성 통합 검사: 실제 빌드한 helper와 임시 HOME을 사용해 자동 시작/인증, 두 서버 동시 실행, 다른 서버를 보존하는 종료, 재시작 및 실행 실패를 확인한다. Keychain·모델·실제 사용자 상태 파일에는 접근하지 않는다. `macos/Checks/verify.sh`에 포함한다.

별도 앱 번들/helper 내장 배포 및 helper 경로 영속 저장은 기존 후속 범위다. 새로운 외부 의존성은 없다.

수동 회귀 검사: --helper 지정 시 자동 연결되고 helper 변경 버튼이 없는지 확인한다. 미지정 시 실행 방법 안내와 비활성 사용량 새로고침을 확인한다. 연결 실패 시 상태 서버 재시작 버튼은 계속 표시한다.
