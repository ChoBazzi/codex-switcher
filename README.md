# Codex Switcher

여러 Codex 계정의 사용량을 확인하고, CLI 대화를 이어가며 사용할 계정을 전환하는 macOS 메뉴바 앱입니다. 로컬 프록시를 통해 Codex CLI와 연결하며, 계정 관리와 전환 상태를 앱에서 확인할 수 있습니다.

현재 소스에서 빌드해 사용하는 개발 버전입니다. 지원하는 CLI 기능과 제약은 [CLI 기능 호환성](docs/cli-feature-compatibility.md) 문서에서 확인할 수 있습니다.

## 주요 기능

- **최대 5개 계정 관리** — 브라우저 로그인으로 계정을 추가하고, 로그아웃한 자리는 다시 사용할 수 있습니다.
- **사용량 확인** — 계정별 잔여량과 요금제를 표시하고, 자동 조회와 수동 새로고침을 제공합니다.
- **계정 전환** — 작업 턴이 끝난 뒤 수동으로 전환하거나, 잔여량이 5% 이하일 때 최신 조회 기준으로 5%를 초과하는 계정으로 자동 전환합니다.
- **CLI 대화 유지** — 지원되는 로컬 도구 이력과 텍스트 요약을 유지하며 계정을 전환합니다.
- **앱 연결용 설정 편집** — `config.toml`과 `AGENTS.md`를 앱 안에서 열고 파일별로 저장합니다.
- **상태·진단** — 메인 대화와 보조 작업의 마지막 오류, 해결 안내, 실행 프록시와 연결용 helper의 빌드를 확인합니다.
- **앱과 프록시 수명 관리** — 앱에서 프록시를 함께 시작하고 종료하며, 다시 실행하면 기존 연결 상태를 복구합니다.

계정 선택이나 복구 준비만으로 모델 요청을 시작하지 않습니다. 실패한 요청은 같은 계정이나 다른 계정으로 자동 재전송하지 않습니다.

## 실행 환경

- macOS 13 이상
- Go 1.24 이상
- Swift 5.9 이상을 제공하는 Xcode 또는 Command Line Tools
- `PATH`에서 실행할 수 있는 Codex CLI

## 빌드 및 실행

저장소 루트에서 실행합니다.

```sh
go build -o bin/switcher-helper ./cmd/switcher-helper
swift run --package-path macos CodexSwitcher --helper "$PWD/bin/switcher-helper"
```

실제 계정을 연결하지 않고 화면만 살펴보려면 데모 모드를 사용할 수 있습니다. 데모는 합성 계정을 표시하며 로그인이나 계정 전환을 실행하지 않습니다.

```sh
swift run --package-path macos CodexSwitcher --demo
```

## 시작하기

1. 앱을 실행하고 메뉴바에서 위젯을 엽니다.
2. **계정 추가**를 눌러 브라우저 로그인을 완료합니다.
3. 사용할 계정의 사용량이 조회되었는지 확인합니다.
4. **Codex CLI 연결 명령 복사**를 누르고, 작업할 프로젝트의 터미널에서 실행합니다.
5. CLI에 요청을 입력합니다. 계정을 수동 전환하려면 현재 작업 턴이 끝난 뒤 앱에서 다른 계정을 선택합니다.

기본 연결 설정은 읽기 전용입니다. 파일 수정이 필요하면 앱의 `config.toml`에서 권한을 설정하거나, 복사한 실행 명령 끝에 다음 옵션을 추가합니다.

```sh
--sandbox workspace-write --ask-for-approval on-request
```

## Codex 설정

앱의 **Codex 설정**에서 앱 연결용 `CODEX_HOME`에 있는 `config.toml`과 `AGENTS.md`를 편집합니다. 일반 CLI의 기본 `~/.codex` 설정 파일을 수정하는 기능은 아닙니다.

파일별로 저장하며, 외부에서 변경된 파일은 덮어쓰지 않도록 충돌을 안내합니다. 프록시 연결과 재시도 비활성화 설정은 유지해야 합니다. 저장한 설정을 적용하려면 현재 CLI 작업을 마치고 종료한 뒤, 앱의 대화 재개 명령으로 같은 기록을 선택합니다.

## 상태와 오류 확인

앱의 **상태·진단**에서 연결 상태, 메인 대화·보조 작업의 마지막 오류와 해결 안내를 확인합니다. **진단 복사**에는 토큰, 계정 식별자, 로컬 경로와 대화 내용을 포함하지 않습니다. 오류 기록은 프록시 메모리에만 보관하므로 프록시 재시작 이전의 오류는 표시되지 않습니다.

연결 시 helper와 실행 중인 프록시의 빌드가 다르거나 확인되지 않으면 안내가 표시됩니다. 새 빌드를 적용하려면 모든 작업을 마친 뒤 앱·프록시를 종료하고 새 앱을 실행하세요. 연결 중 재빌드한 파일은 다시 연결할 때 확인합니다.

## 종료와 대화 복구

**앱·프록시 종료** 또는 일반 앱 종료는 프록시 종료를 확인한 뒤 앱을 닫습니다. 모델 요청, 도구 실행, 계정 작업이 진행 중이면 종료를 보류하고 이유를 표시합니다.

앱을 다시 켜면 기존 연결 주소와 대화 상태를 복구합니다. CLI가 계속 실행 중이라면 같은 터미널에서 새 입력으로 이어갈 수 있습니다. 앱이 꺼져 있는 동안에는 모델 요청을 보낼 수 없으며, 앱이 비정상 종료되면 프록시가 남아 있을 수 있습니다.

실패하거나 중단된 요청은 자동으로 재실행하지 않습니다. CLI가 입력 대기 상태인지 확인하고, 앱에서 필요한 복구 준비를 마친 뒤 새 지시를 입력합니다.

## 지원 범위

- 하나의 앱 연결은 하나의 루트 CLI 대화를 대상으로 합니다. `/new`, `/fork` 또는 별도의 CLI·IDE 대화를 같은 연결에 공유하는 방식은 지원하지 않습니다.
- 리뷰·서브에이전트·자동 승인 검토는 별도 보조 대화로 처리하며, 시작 계정에 고정합니다. 보조 작업 중에는 계정 전환이 잠깁니다.
- 텍스트 기반 대화 압축을 지원합니다. 루트 대화의 native 암호화 압축 결과는 생성 계정에 고정되며, 보조 대화의 native 압축은 지원하지 않습니다.
- 이미지, 서버 실행 도구를 포함한 모든 CLI 기능의 호환성을 보장하지는 않습니다. 세부 검증 범위는 [호환성 문서](docs/cli-feature-compatibility.md)를 참고하세요.

## 인증 정보와 로컬 통신

계정 인증 정보는 macOS Keychain에 저장합니다. 프록시와 제어 API는 기본적으로 로컬 loopback 주소에만 바인딩합니다. 계정에 종속된 continuation 식별자는 다른 계정에 전달하지 않습니다.

암호화된 내부 이력은 실제 계정·사용자 신원과 로그인 등록 단위로 구분합니다. 같은 슬롯에 다시 등록해도 이전 인증의 암호화 이력을 그대로 전송하지 않습니다.

## 개발 및 문서

전체 개발 검증은 저장소 루트에서 실행합니다.

```sh

```

검증 스크립트는 Go 검사, helper·Swift 빌드, 합성 데이터를 사용하는 CLI 통합 검사와 UI 검사를 수행합니다. 실제 계정과 모델을 사용하는 환경의 검증을 대체하지는 않습니다.
