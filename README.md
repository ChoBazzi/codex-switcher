# Codex Switcher

여러 Codex 계정의 사용량을 확인하고, CLI 대화를 이어가며 사용할 계정을 전환하는 macOS 메뉴바 앱입니다. 로컬 프록시를 통해 Codex CLI와 연결하며, 계정 관리와 전환 상태를 앱에서 확인할 수 있습니다.

현재 소스에서 빌드해 사용하는 개발 버전입니다. 지원하는 CLI 기능과 제약은 [CLI 기능 호환성](docs/cli-feature-compatibility.md) 문서에서 확인할 수 있습니다.

## 주요 기능

- **최대 5개 계정 관리** — 브라우저 로그인으로 계정을 추가하고, 로그아웃한 자리는 다시 사용할 수 있습니다.
- **사용량 확인** — 계정별 잔여량과 요금제를 표시하고, 자동 조회와 수동 새로고침을 제공합니다.
- **계정 전환** — 작업 턴이 끝난 뒤 수동으로 전환하거나, 잔여량이 5% 이하일 때 최신 조회 기준으로 5%를 초과하는 계정으로 자동 전환합니다.
- **최대 5개 독립 연결** — 여러 터미널의 대화를 동시에 실행하고, 연결별 계정·실패 상태·설정을 관리합니다.
- **CLI 대화 유지** — 지원되는 로컬 도구 이력과 텍스트 요약을 유지하며 계정을 전환합니다.
- **앱 연결용 설정 편집** — `config.toml`과 `AGENTS.md`를 앱 안에서 열고 파일별로 저장합니다.
- **상태·진단** — 메인 대화와 보조 작업의 마지막 오류, 해결 안내, 실행 프록시와 연결용 helper의 빌드를 확인합니다.
- **앱과 프록시 수명 관리** — 앱에서 프록시를 함께 시작하고 종료하며, 다시 실행하면 기존 연결 상태를 복구합니다.

계정 선택이나 복구 준비만으로 모델 요청을 시작하지 않습니다. 작업 중 명시적인 사용량 소진(`usage_limit_reached`)이 발생하면, 해당 시도의 출력이 전달되기 전에 다른 사용 가능한 계정으로 전환해 같은 CLI 요청을 이어갑니다. 일반 오류나 이미 출력이 전달된 요청은 자동 재전송하지 않습니다.

## 실행 환경

- macOS 13 이상
- Go 1.24 이상
- Swift 5.9 이상을 제공하는 Xcode 또는 Command Line Tools
- `PATH`에서 실행할 수 있는 Codex CLI

## 빌드 및 실행

저장소 루트에서 실행합니다.

```sh
go build -o bin/switcher-helper ./cmd/switcher-helper
swift run --package-path macos CodexSwitcher --helper "$PWD/bin/switcher-helper"
```

실제 계정을 연결하지 않고 화면만 살펴보려면 데모 모드를 사용할 수 있습니다. 데모는 합성 계정을 표시하며 로그인이나 계정 전환을 실행하지 않습니다.

```sh
swift run --package-path macos CodexSwitcher --demo
```

## 시작하기

1. 앱을 실행하고 메뉴바에서 위젯을 엽니다.
2. **계정 추가**를 눌러 브라우저 로그인을 완료합니다.
3. 사용할 계정의 사용량이 조회되었는지 확인합니다.
4. **Codex CLI 연결 명령 복사**를 누르고, 작업할 프로젝트의 터미널에서 실행합니다.
5. 다른 대화도 동시에 실행하려면 앱에서 **새 연결**을 누르고, 새 연결의 명령을 다른 터미널에서 실행합니다. 각 연결의 명령은 해당 대화에만 사용하세요.
6. CLI에 요청을 입력합니다. 계정을 수동 전환하려면 현재 작업 턴이 끝난 뒤 앱에서 다른 계정을 선택합니다.

기본 연결 설정은 읽기 전용입니다. 파일 수정이 필요하면 앱의 `config.toml`에서 권한을 설정하거나, 복사한 실행 명령 끝에 다음 옵션을 추가합니다.

```sh
--sandbox workspace-write --ask-for-approval on-request
```

## Codex 설정

앱에서 확인할 연결을 선택한 뒤 **Codex 설정**에서 해당 연결용 `CODEX_HOME`에 있는 `config.toml`과 `AGENTS.md`를 편집합니다. 일반 CLI의 기본 `~/.codex` 설정 파일을 수정하는 기능은 아닙니다.

파일별로 저장하며, 외부에서 변경된 파일은 덮어쓰지 않도록 충돌을 안내합니다. 프록시 연결과 재시도 비활성화 설정은 유지해야 합니다. 저장한 설정을 적용하려면 현재 CLI 작업을 마치고 종료한 뒤, 앱의 대화 재개 명령으로 해당 대화를 이어갑니다. 새 연결은 별도 홈을 사용하므로 사용자 설정도 연결별로 지정합니다.

## 상태와 오류 확인

앱의 **상태·진단**에서 연결 상태, 메인 대화·보조 작업의 마지막 오류와 해결 안내를 확인합니다. **진단 복사**에는 토큰, 계정 식별자, 로컬 경로와 대화 내용을 포함하지 않습니다. 오류 기록은 프록시 메모리에만 보관하므로 프록시 재시작 이전의 오류는 표시되지 않습니다.

연결 시 helper와 실행 중인 프록시의 빌드가 다르거나 확인되지 않으면 안내가 표시됩니다. 새 빌드를 적용하려면 모든 작업을 마친 뒤 앱·프록시를 종료하고 새 앱을 실행하세요. 연결 중 재빌드한 파일은 다시 연결할 때 확인합니다.

요청 본문 수신은 30초·4 MiB로 제한합니다. 시간 초과, 크기 초과, 인증 만료, Keychain 접근 실패는 각각 다른 원인으로 안내합니다. 본문 수신 제한은 정상적인 모델 응답 스트리밍 시간을 제한하지 않습니다.

CLI 요청이 취소되면 인증 갱신 대기에서 빠지고, 전송 전에 취소를 확인한 모델 요청은 보내지 않습니다. 이미 시작한 토큰 갱신은 새 인증 정보를 잃지 않도록 교환과 저장을 마치므로 잠시 작업 중으로 표시될 수 있습니다. 취소된 요청은 자동 재전송하지 않습니다.

앱의 세션 카드와 **상태·진단**에서 계정별 **인증 대기 중**, **토큰 갱신 중**, **취소 후 인증 갱신 마무리 중**을 확인할 수 있습니다. 기존 상태 조회 주기로 갱신하며, 메인·보조 작업과 사용량 조회의 인증 활동을 합산합니다. 구버전 프록시에서는 인증 상태가 미확인으로 표시될 수 있습니다.

다른 계정이 토큰을 갱신 중이어도, 갱신이 필요 없는 계정의 모델·사용량 요청은 해당 갱신 완료를 기다리지 않습니다. 같은 계정의 요청은 갱신 결과가 안전하게 저장된 뒤 진행합니다.

한도 오류는 HTTP 429 상태만으로 판단하지 않습니다. JSON 오류의 `type`/`code` 또는 출력 전 SSE 오류의 `usage_limit_reached`를 확인합니다. 일반 `rate_limit_exceeded`, 인증 오류, 네트워크 오류, 알 수 없는 코드에는 자동 전환을 적용하지 않습니다. 대상 계정은 최신 조회 잔여량이 5%를 초과해야 하고, 같은 요청에서 이미 시도한 계정으로 돌아가지 않습니다.

자동 전환 시 완료된 도구 호출·결과와 텍스트를 유지하고, 계정에 종속된 reasoning 및 원래 호출 ID는 전달하지 않습니다. 같은 사용자 턴의 후속 요청도 이 변환을 유지합니다. 프록시가 완료된 로컬 도구를 다시 실행하지는 않습니다. 암호화 압축 이력, 대안 계정 부재, 중간 출력 이후의 소진 등은 자동으로 복구하지 못하며 기존 복구 준비가 필요합니다.

보조 작업은 연결 하나에 누적 128개까지 기록하며 **상태·진단**에서 남은 용량을 확인합니다. 완료·실패한 기록도 재전송 차단을 위해 남으므로 일반 재시작으로 용량이 초기화되지 않습니다.

### 보조 작업 한도에 도달했을 때 새 연결 준비

1. 모든 모델·도구 작업을 마치고 연결된 CLI를 종료합니다. 도구 대기가 남아 있으면 실제 도구 종료를 확인한 뒤 앱에서 명시적으로 중단 처리합니다.
2. 프로젝트 루트에서 `./bin/switcher-helper proxy-stop --new-session --connection N`을 실행합니다. N에는 교체할 연결 번호(1~5)를 넣습니다. 작업 중이면 거절되며 실패 요청을 다시 실행하지 않습니다.
3. 앱에서 **모델 프록시 다시 연결**을 누르고 새 연결 명령을 복사해 새 CLI 대화를 시작합니다.

이 절차는 모든 연결이 대기 상태일 때 프록시를 종료하고, 지정한 연결의 주소·연결 키·CLI 홈만 새로 만듭니다. 다른 연결은 다음 시작에서 기존 상태로 복구합니다. 이전 CLI 홈과 대화 기록은 삭제하지 않지만, 이전 터미널 연결을 그대로 이어가는 절차는 아닙니다. 별도로 편집한 설정과 필요한 문맥은 새 홈·대화에서 확인하세요.

## 종료와 대화 복구

**앱·프록시 종료** 또는 일반 앱 종료는 프록시 종료를 확인한 뒤 앱을 닫습니다. 선택한 연결을 포함해 어느 연결에서든 모델 요청, 도구 실행 또는 계정 작업이 진행 중이면 종료를 보류하고 이유를 표시합니다.

앱을 다시 켜면 기존 연결 주소와 대화 상태를 복구합니다. CLI가 계속 실행 중이라면 같은 터미널에서 새 입력으로 이어갈 수 있습니다. 앱이 꺼져 있는 동안에는 모델 요청을 보낼 수 없으며, 앱이 비정상 종료되면 프록시가 남아 있을 수 있습니다.

실패하거나 중단된 요청은 자동으로 재실행하지 않습니다. CLI가 입력 대기 상태인지 확인하고, 앱에서 필요한 복구 준비를 마친 뒤 새 지시를 입력합니다.

## 지원 범위

- 앱에서 최대 5개의 연결을 만들 수 있고, 각 연결은 하나의 루트 CLI 대화를 대상으로 합니다. 여러 연결에서 같은 계정을 사용할 수 있으며 계정 사용량·인증은 공유합니다. 연결 선택은 다른 대화의 작업을 중단하지 않습니다.
- 새 대화는 **새 연결**에서 시작합니다. `/new`, `/fork` 또는 별도의 CLI·IDE 대화를 같은 연결에 공유하는 방식은 지원하지 않습니다.
- 리뷰·서브에이전트·자동 승인 검토는 별도 보조 대화로 처리합니다. 일반 요청은 시작 계정을 유지하고, 출력 전 명시적 사용량 소진에만 해당 보조 대화의 계정을 전환합니다. 보조 작업 중에는 해당 연결의 계정 전환이 잠깁니다. 로그인·로그아웃은 모든 연결의 작업이 끝나야 합니다.
- 에이전트의 암호화 작업 지시는 같은 연결에서 성공한 응답으로 생성됐고 인증 신원이 일치할 때 보존합니다. 소유권을 확인할 수 없으면 지시를 삭제하지 않고 요청을 거절합니다. 이 암호화 협업 이력이 포함된 요청은 다른 계정으로 자동 전환할 수 없습니다. 지원 이전 버전에서 생성된 이력은 새 연결의 새 대화가 필요할 수 있습니다.
- 텍스트 기반 대화 압축을 지원합니다. 루트 대화의 native 암호화 압축 결과는 생성 계정에 고정되며, 보조 대화의 native 압축은 지원하지 않습니다.
- 이미지, 서버 실행 도구를 포함한 모든 CLI 기능의 호환성을 보장하지는 않습니다. 세부 검증 범위는 [호환성 문서](docs/cli-feature-compatibility.md)를 참고하세요.

## 인증 정보와 로컬 통신

계정 인증 정보는 macOS Keychain에 저장합니다. 프록시와 제어 API는 기본적으로 로컬 loopback 주소에만 바인딩합니다. 계정에 종속된 continuation 식별자는 다른 계정에 전달하지 않습니다.

암호화된 내부 이력은 실제 계정·사용자 신원과 로그인 등록 단위로 구분합니다. 같은 슬롯에 다시 등록해도 이전 인증의 암호화 이력을 그대로 전송하지 않습니다.

helper가 같은 계정·사용자임을 확인하고 토큰 갱신을 저장한 경우에는 기존 이력 소유권을 유지합니다. 재로그인이나 확인되지 않은 인증 변경은 별개로 처리합니다. 실제 서비스의 갱신 후 암호화 이력 호환성은 별도 검증이 필요합니다.

## 개발 및 문서

전체 개발 검증은 저장소 루트에서 실행합니다.

```sh
sh macos/Checks/verify.sh
```

검증 스크립트는 Go 검사, helper·Swift 빌드, 합성 데이터를 사용하는 CLI 통합 검사와 UI 검사를 수행합니다. 실제 계정과 모델을 사용하는 환경의 검증을 대체하지는 않습니다.

GitHub Actions는 macOS에서 같은 검증을 실행하며 호환성 검사에 사용하는 CLI를 `0.155.1`로 고정합니다. PR 및 `main`·`dev` push 때 실행하며, 병합 필수 검사 지정은 저장소의 브랜치 보호 설정에서 별도로 적용합니다.
